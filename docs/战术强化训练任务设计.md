# 战术强化训练活动任务设计

## 概述

战术强化训练（通称巧克力/南瓜）是同一个活动，操作完全一致。

| 项目 | 内容 |
|------|------|
| 流水线文件 | `resource/base/pipeline/TacticalTraining.json` |
| 入口节点 | `TacticalTraining` |
| 节点前缀 | `TT_` |
| 活动模板 | `战术强化训练.png`（TemplateMatch，ROI [429, 69, 289, 52]） |
| 参考实现 | `LRentaisen.json`（陆联，更复杂）、`Expedition.json`（远征同步集成） |

## GUI 选项

| 选项 | 类型 | 说明 |
|------|------|------|
| 重复次数 | numeric | 框架内置，`Repeatable: true` |
| 选择难度 | select | 初级/中级/上级，默认初级，覆盖 `TT_ClickDifficulty.target` |
| 选择部队 | select | 部队一 ~ 部队五，默认部队一，覆盖 `TT_ClickTargetTeam.target` |
| 换队长 | checkbox | 开启后将 `TT_DragCaptain` 挂入 `TT_CaptainHub.next`，仅支持队内拖拽方式 |
| 不购买门票 | checkbox | 开启后 `TT_IsSilhouettePopup.next` 改为 `["TT_ConfirmSilhouette", "TT_TerminateNoTicket"]`，任务终止 |
| 同步远征 | switch | 全队忙线后启动远征计时器，回到活动继续出阵 |

## 主枢纽 `TT_DetectWhereAmI`

```json
"TT_DetectWhereAmI": {
    "pre_delay": 0,
    "next": [
        "TT_IsAnnouncementPopup",
        "TT_IsLoginReward",
        "TT_IsEventPage",
        "TT_IsSilhouettePopup",
        "TT_IsTicketReplenishPage",
        "TT_CheckHomeBrightness",
        "TT_IsTeamSelect",
        "TT_IsSwordSelect",
        "TT_IsSortie",
        "TT_HasExpeditionReturn_Exp",
        "TT_HasExpeditionReturn_Title",
        "TT_IsBattleResult_Exp",
        "TT_IsSwordDropColor",
        "TT_IsConnectionInterrupted",
        "TT_IsGameIcon",
        "TT_IsLoginButton",
        "TT_IsGameUpdatePopup",
        "TT_IsInGameUpdatePopup",
        "TT_IsInternalReport",
        "TT_FallbackWait"
    ],
    "timeout": 120000,
    "on_error": ["TT_RestartGame"]
}
```

> 节点说明：
> - `TT_IsBattleResult_Exp`：OCR "经验"，战斗结算页点击关闭
> - `TT_IsSwordDropColor`：ColorMatch 刀剑掉落颜色，点击关闭再进
> - `TT_IsConnectionInterrupted`：OCR "连接中断"，点击重连
> - 无 `TT_IsSpecialDrop`：该活动无特殊掉落画面
> - 无 `TT_CheckSwordDropAfterSpecial`：该活动无特殊掉落后的额外检测需求
> - 无 `TT_IsTicketPopup` / `TT_IsReplenishDone`：门票补给只在更新剪影链路中弹出

## 主流程

```
TacticalTraining（入口）
  → TT_DetectWhereAmI（主枢纽）
     ├── TT_IsAnnouncementPopup → 点击关闭，回到枢纽
     ├── TT_IsLoginReward → 连击关闭，回到枢纽
     ├── TT_IsEventPage（TemplateMatch 活动页面.png）
     │     → TT_ClickDifficulty（点击难度按钮）
     │       → TT_VerifyEventPage（TemplateMatch 活动页面.png 双重确认）
     │         → TT_CheckSilhouette（OCR "更新" [308,407,140,36] → Click）
     │              ├─ 命中 → 进入剪影更新界面，next: [TT_IsSilhouettePopup, TT_IsSwordDropColor, TT_CheckSilhouette]
     │              └─ 未命中 → TT_EnterEvent（点击进入按钮）
     │
     ├── TT_IsSilhouettePopup → 确认更新 / TT_TicketGate（门票入口）
     │
     ├── TT_IsTicketReplenishPage → 更新令牌补充页面
     │
     ├── TT_CheckHomeBrightness → TT_IsHome → TT_NavigateToActivity
     ├── TT_IsSortie → TT_OnSortieScreen → 回到枢纽
     ├── TT_HasExpeditionReturn_Exp / _Title → 关闭远征归来弹窗
     ├── TT_IsBattleResult_Exp → 点击关闭战斗结算页
     ├── TT_IsSwordDropColor → 点击关闭掉落页
     ├── TT_IsConnectionInterrupted → 点击重连
     ├── TT_IsTeamSelect → 部队选择流程
     └── 闪退恢复节点（IsGameIcon/IsLoginButton/...）
```

    "recognition": { "type": "OCR", "param": { "roi": [561, 1, 160, 49], "expected": "部队选择" } },

    "action": { "type": "Click", "param": { "target": [154, 93, 1, 1] } },
    "next": ["TT_CheckCaptainColor"],
    "pre_delay": 100,
    "post_delay": 800

## 同步远征集成

与陆联完全相同的模式。同步远征开启时，通过 `pipeline_override` 将 TT 任务与远征流水线交叉连接：

```
TT_IsHome → Expedition（先检查远征）
  → ...远征派遣...
    → E_AllTeamsBusy → E_TimerStart → TT_NavigateToActivity（回到活动）
      → ...出阵循环...
```

`TT_IsTeamSelect → E_CheckTimerExpired` 由智能调度开启 case 注入（与陆联 `LR_IsTeamSelect` 处理方式相同），不在 `TT_同步远征` 中设置。

**E_TimerStart 行为**：`ExpeditionTimerAction.Run()` 根据 `IsSmartSchedulingEnabled()` 分支——开启时 OCR 扫描 + 启计时 + 关面板；关闭时仅关面板。

| 覆盖节点 | 覆盖值 | 说明 |
|----------|--------|------|
| `TT_IsHome.next` | `["Expedition"]` | 回到本丸时跳远征 |
| `E_AllTeamsBusy.next` | `["E_TimerStart"]` | 忙线启计时 |
| `E_TimerStart.next` | `["TT_NavigateToActivity"]` | 计时器启动后回到活动 |
| `E_ClickBackToHome.next` | `["TT_WaitRefresh"]` | 远征结束等待刷新 |
| `E_CheckTimerExpired.next` | `["TT_ClickTargetTeam"]` | 未过期继续出阵 |
| `E_CheckTimerExpired.on_error` | `["E_GoHome"]` | 已过期回远征 |
| `E_SelectMapN.action` | `ExpeditionMapSelectAction` | 直接选图 |
| `E_ClickSmallMapN.enabled` | `false` | 禁用小地图点击 |
| `TT_WaitRefresh.enabled` | `true` | 启用等待刷新 |

智能调度开启 case 额外注入：
| 覆盖节点 | 覆盖值 | 说明 |
|----------|--------|------|
| `TT_IsTeamSelect.next` | `["E_CheckTimerExpired"]` | 选队前检查计时器 |

### 轮次完成判断

刀剑掉落识别到后，等待 1s（post_delay），然后优先检测活动页面是否重现——命中则一轮完成。

```json
"TT_CheckRoundComplete": {
    "recognition": { "type": "TemplateMatch", "param": { "roi": [429, 69, 289, 52], "template": "战术强化训练.png", "green_mask": true, "threshold": [0.98] } },
    "next": []
}
```

> `TT_CheckRoundComplete` 命中后 `next: []` 终止当前轮，框架按 `repeatable + repeat_count` 重启下一轮。未命中则回退到 `TT_DetectWhereAmI` 继续枢纽循环。

## 设计要点

- **模板**：`战术强化训练.png`
- **剪影链路**：`TT_IsSilhouettePopup` OCR 识别"更新剪影"弹窗并点击确认
- **剪影点击节点的 next**：同时包含剪影更新链路和刀剑掉落检测，避免更新过程中因掉落弹窗卡死
- **门票不同于陆联**：只在剪影更新链路中弹出，不在即刻出阵后出现
- **无战斗循环**：点完即刻出阵直接回枢纽，不跟踪行军/阵形/战斗结果
- **全队耗尽终止**：部队一~五全部未命中颜色条件时终止任务
- **换队长同陆联**：仅支持队内拖拽方式，`TT_DragCaptain` 默认不挂载，由选项注入
- **轮次完成**：刀剑掉落 → 等待 1s → 活动页面重现即为完成一轮，`TT_CheckRoundComplete`（next: []）触发框架重启
- **on_error 规范**：所有 Click 节点若 `next` 指向识别节点，必须配置 `on_error`；路由节点同理

# 长期远征计划 — 设计文档

> 创建日期：2026-07-19 | 最后更新：2026-07-21

## 概述

全局 switch 选项，默认关闭。启用后在每次派出远征队伍之前，OCR 该队伍六个位置的疲劳值。若有刀剑疲劳低于用户设定阈值，则自动跳转 1-1 单次出阵刷花，刷完后回到本丸重新判断，直到该队伍所有刀剑疲劳均满足阈值，再继续远征派遣。

与现有「刷花」任务的关系：**不复用刷花 pipeline**。刷花流程内嵌在远征流水线中。

## 配置项

| 选项 | 类型 | 说明 |
|------|------|------|
| 长期远征计划 | switch | 全局开关，默认关闭 |
| 疲劳阈值 | input（int） | 默认 91，疲劳值低于此数触发刷花 |

## 主流程

```
E_CheckTeamN（OCR "机"/"队员" 判断待机）
    ↓ 命中（该部队空闲）

    ↓                                                                    （现有远征派遣链路）
```

**关键链路**：长期远征计划开启时，`pipeline_override` 将 `E_MarkTeamN.next` 从 `E_StartExpedition` 改为 `E_UseTeamRecordN`。关闭时恢复原链路。

## 关键设计决策

### 循环终止条件：最低疲劳值 ≥ 用户阈值

> 游戏中的"疲劳值"实际是心情值，数值越高越好（高 = 心情好，低 = 疲惫）。

每轮解散换队长后，OCR 首位刀剑（新队长）的数值：

- 新队长值 ≥ 阈值 → 心情良好，跳出循环回家
- 新队长值 < 阈值 → 仍需刷花，即刻出阵进入战斗

### 特供换队长：喜爱筛选 + 颜色匹配

不沿用全局「换队长方式」（马匹/刀装/拖拽），使用独立流程：

1. `E_FlowerDissolve` ColorMatch 循环叉掉 2-6 号位，仅剩旧队长
2. 点击"喜爱"标签进入喜爱筛选页面
3. ColorMatch「决定」按钮列，取最高处命中像素点击——该刀剑与旧队长**交换位置**
4. 交换后新刀剑在 1 号位，旧队长移至新刀剑原位置，2 号位依旧为空，1-1 单骑出阵
5. 未命中则上滑翻页重试

与普通换队长的差异：

- 普通：按马匹/刀装排序 → 点疲劳最低的刀剑 → 拖拽到队长位
- 特供：叉掉 2-6 号位 → 仅剩旧队长 → 喜爱 → DetectSortOrder → ColorMatch 交换

## 自定义动作

| 类 | 说明 |
|------|------|
| `FatigueCheckAction` | OCR 疲劳值，check_all/check_captain 双模式。阈值 ≥ 91 默认，从全局选项读取 |
| `FlowerStateTracker` | 静态类：TargetTeam、LoopCount（30 轮上限）、CurrentFatigueLowest |
| `SelectFlowerTeamAction` | 读取 TargetTeam，点击对应部队按钮 |
| `PageScrollAndHoldAction` | Swipe 500ms + 终点 TouchDown 保持 1s |

## 与现有系统的交互

- **与远征智能调度**：两个独立开关。都开启时：检查疲劳 → 刷花 → 派遣 → OCR 计时
- **与同步远征**：合战场/陆联勾选同步远征后，回本丸检查远征时自然经过疲劳检查

## 风险与边界情况

1. **闪退恢复**：`E_FlowerBattleHub` 内置完整闪退链 + timeout 120s + `E_RestartGame` 兜底
2. **无限循环**：30 轮上限（`FlowerStateTracker.MaxLoops`）
3. **部队为空**：全空槽位跳过疲劳检测
4. **多队伍串行**：五队依次检查，完事后回本丸继续下一队
5. **pipeline_override**：`interface.json` 中 `E_MarkTeamN.next` → `E_UseTeamRecordN`

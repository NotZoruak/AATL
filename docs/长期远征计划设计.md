# 长期远征计划 — 设计文档

> 创建日期：2026-07-19

## 概述

全局 switch 选项，默认关闭。启用后在每次派出远征队伍之前，OCR 该队伍六个位置的疲劳值。若有刀剑疲劳低于用户设定阈值，则自动跳转 1-1 单次出阵刷花，刷完后回到本丸重新判断，直到该队伍所有刀剑疲劳均满足阈值，再继续远征派遣。

与现有「刷花」任务的关系：**不复用刷花 pipeline**。长期远征计划的刷花流程直接内嵌在远征流水线中，走"右上角目录 → 出阵 → 1-1 → 选队 → 解散 → 换队长 → 单次出阵"的独立链路。

## 配置项

| 选项 | 类型 | 说明 |
|------|------|------|
| 长期远征计划 | switch | 全局开关，默认关闭 |
| 疲劳阈值 | input（int） | 默认 40，疲劳值低于此数的刀剑触发刷花 |

## 主流程

```
E_CheckTeamN（OCR "机"/"队员" 判断待机）
    ↓ 命中（该部队空闲）
E_MarkTeamN（DispatchLogAction mode:"mark"，记录当前部队编号）
    ↓
E_CheckFatigueN（OCR 六个位置疲劳值）
    ├── 全部 ≥ 阈值 → E_StartExpedition → ...（正常远征派遣）
    └── 有 < 阈值 的刀剑
        ↓
        │  刷花循环（持续循环，直到最低疲劳 > 阈值）
        │  ┌──────────────────────────────────────────────┐
        │  │ E_FlowerNavigate（右上角目录 → 出阵 → 1-1）    │
        │  │     ↓                                        │
        │  │ E_FlowerTeamSelectN（选择当前远征部队）         │
        │  │     ↓                                        │
        │  │ E_FlowerDissolve（解散队伍）                   │
        │  │     ↓                                        │
        │  │ [使用部队记录，恢复该队伍的预设编队]             │
        │  │     ↓                                        │
        │  │ E_FlowerCheckCaptain（确认升序 → OCR 首位疲劳） │
        │  │     ├── 最低疲劳 > 阈值 → 跳出循环             │
        │  │     └── 最低疲劳 ≤ 阈值                        │
        │  │          ↓                                    │
        │  │     E_FlowerCaptain（颜色匹配找可用刀剑 → 点击）│
        │  │          ↓                                    │
        │  │     E_FlowerSortie（点击出阵）                │
        │  │          ↓                                    │
        │  │     [战斗：行军 → 阵形 → 结果 → 回本丸]        │
        │  └──────────────────────────────────────────────┘
        ↓
E_FlowerDone（全部刷完）
    ↓
对该队伍使用部队记录 → 通过目录回到本丸 → 继续远征派遣链路
```

**关键链路**：开启长期远征计划后，`E_MarkTeamN.next` 从 `E_StartExpedition` 改为 `E_CheckFatigueN`；`E_CheckFatigueN` 全部合格时 `next` 走 `E_StartExpedition`。

**E_MarkTeamN 与使用部队记录的区别**：
- `E_MarkTeamN`（`DispatchLogAction`）：MATR 内部日志记录，标记当前正在处理哪个部队
- 使用部队记录：游戏内置的编队保存/恢复功能（类似补充刀装），在解散队伍后恢复预设编队

## 关键设计决策

### 循环终止条件：最低疲劳 > 用户阈值

不预计算轮数。每轮换队长之前确认升序排列，读取首位（疲劳最低）刀剑的疲劳值：

- 最低疲劳 > 阈值 → 该队伍刷花完成，跳出循环
- 最低疲劳 ≤ 阈值 → 颜色匹配找可用刀剑，出阵刷花，回本丸后继续下一轮

优势：不受 OCR 单次误差影响，循环中持续矫正；阈值由用户自定义，灵活适配不同需求。

### 特供换队长：喜爱筛选 + 颜色匹配

刷花链路中的换队长不沿用全局「换队长方式」（马匹/刀装/拖拽），使用独立的专用流程：

1. 在刀剑筛选页面选择"喜爱"标签
2. 对「决定」按钮所在的整列（一个纵向长条区域）进行 ColorMatch
3. 取所有命中像素中最高处的那个，点击其所在位置选择对应刀剑
4. 如果整列均未命中，上滑翻页后重新 ColorMatch

与普通换队长的差异：

- 普通换队长：按马匹/刀装排序 → 直接点疲劳最低的刀剑 → 拖拽到队长位
- 特供换队长：按喜爱筛选 → ColorMatch 按钮列找第一个可用 → 点击选中

### 为什么解散队伍后用部队记录恢复

解散队伍后通过部队记录（游戏内置的编队保存功能，操作方式类似补充刀装）恢复该远征队伍的预设编队，确保刀剑顺序与远征时一致。

### 刷花完成后使用部队记录

刷花结束后，返回队伍状态面板对该队伍执行一次部队记录读取（类似补充刀装的编队恢复机制），然后通过目录回本丸继续远征派遣。

### 战斗流程复用

从出阵点击到回到本丸的整个战斗链路（行军检测、阵形选择、战斗结果点击等），从 `Sortie.json` 或 `FlowerBrush.json` 中复制关键节点到 `Expedition.json`，前缀使用 `E_Flower`。不需要检非、重伤检测等复杂逻辑——1-1 不会遇到检非，且疲劳刷花时即使轻伤也无所谓。

## 所需节点清单

### 派遣前节点（每个部队一组，N=1~5）

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_MarkTeamN` | 自定义动作 | `DispatchLogAction mode:"mark" team:N`，记录当前部队编号。开启长期远征计划后 `next` 改为 `E_CheckFatigueN` |

### 疲劳检测节点（每个部队一组，N=1~5）

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_CheckFatigueN` | OCR × 6 位置 | 复用 DragCaptainAction 的 FatigueRois，读六个位置疲劳值与阈值比较。全部 ≥ 阈值 → `E_StartExpedition`；有 < 阈值 → 进入刷花循环 |

### 导航节点

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerNavigate` | 点击链路 | 右上角目录 → 出阵 → 点选維新 → 点选函館（1-1） |
| `E_FlowerTeamSelectN` | Click | 点击对应部队按钮 |
| `E_FlowerDissolve` | Click | 点击解散按钮 |

### 刷花链路节点

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerCheckCaptain` | OCR | 确认升序排列 → OCR 首位（最低疲劳）刀剑的疲劳值。> 阈值则跳出循环，≤ 阈值则继续换队长 |
| `E_FlowerCaptain` | ColorMatch 链路 | 特供换队长：点击喜爱标签 → ColorMatch「决定」按钮列（纵向长条）→ 点击第一个命中像素 → 未命中则下滑翻页 |
| `E_FlowerSortie` | Click | 点击出阵按钮 |

### 战斗流程节点

从 `Sortie.json` / `FlowerBrush.json` 中复制以下节点到 `Expedition.json`，前缀 `E_Flower`：

| 节点 | 说明 |
|------|------|
| `E_FlowerMarching` | 行军检测 |
| `E_FlowerFormation` | 阵形选择（默认逆行阵） |
| `E_FlowerBattleResult` | 战斗结果点击 |
| `E_FlowerReturnHome` | 回到本丸检测 |

### 循环结束节点

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerDone` | 路由 | 刷花循环出口。跳转回队伍状态面板，对该队伍使用部队记录，然后通过目录回到本丸继续远征派遣 |

## 自定义动作

| 类 | 说明 |
|------|------|
| `FatigueCheckAction` | OCR 六个位置疲劳值，返回最低值和 < 阈值的判定结果。供 `E_CheckFatigueN` 和 `E_FlowerCheckCaptain` 共用 |
| `FlowerStateTracker` | 静态类，存储当前刷花状态：目标部队编号。跨节点共享 |

## 与现有系统的交互

### 与远征智能调度的关系

两个全局开关独立工作，互不冲突：

- 长期远征计划：控制**派遣前**是否检查疲劳 + 刷花
- 远征智能调度：控制**派遣后**是否 OCR 剩余时间动态计时

都开启时流程为：
```
检查疲劳 → （如需刷花）→ 刷花完成 → 派遣远征 → OCR 剩余时间 → 智能计时
```

### 与同步远征的关系

长期远征计划在远征流水线中触发，因此同步远征（合战场/陆联/地下城勾选同步远征）自然也会受益——回本丸检查远征时会经过疲劳检查 → 刷花 → 派遣。

## 风险与边界情况

1. **刷花过程中游戏闪退**：Expedition 枢纽的闪退恢复节点（`E_IsGameIcon` 等）仍然生效。闪退恢复后进入 `E_DetectWhereAmI` 重新检测。`FlowerStateTracker` 使用 static 变量，进程内不丢失，闪退恢复后可继续。

2. **无限循环保护**：极端情况下疲劳值卡在某个非 100 的值（如刀剑已满级），设置最大循环上限 30 轮，超过则放弃刷花继续远征。

3. **部队为空**：如果远征队伍没有编入刀剑（全部空槽位），`E_CheckFatigueN` 返回"无可用位置"，直接跳过进入远征派遣。

4. **多队伍串行**：五个部队依次检查，队伍一的刷花完成后 `E_FlowerDone` 中对该队伍使用部队记录，回到本丸后继续检查队伍二。

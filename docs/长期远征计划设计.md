# 长期远征计划 — 设计文档

> 创建日期：2026-07-19

## 概述

全局 switch 选项，默认关闭。启用后在每次派出远征队伍之前，OCR 该队伍六个位置的疲劳值。若有刀剑疲劳低于用户设定阈值，则自动跳转 1-1 单次出阵刷花，刷完后回到本丸重新判断，直到该队伍所有刀剑疲劳均满足阈值，再继续远征派遣。

与现有「刷花」任务的关系：**不复用刷花 pipeline**。长期远征计划的刷花流程直接内嵌在远征流水线中，走"右上角目录 → 出阵 → 1-1 → 选队 → 解散 → 换队长 → 单次出阵"的独立链路。

## 配置项

| 选项 | 类型 | 说明 |
|------|------|------|
| 长期远征计划 | switch | 全局开关，默认关闭 |
| 疲劳阈值 | input（int） | 默认 91，疲劳值低于此数的刀剑触发刷花 |

## 主流程

```
E_CheckTeamN（OCR "机"/"队员" 判断待机）
    ↓ 命中（该部队空闲）
E_SelectTeamN → E_VerifyScreenN → E_SelectMapN → E_ClickSmallMapN → E_ConfirmDispatchN
    ↓                                                                    （现有远征派遣链路）
E_SelectTeamBtnN（OCR "部队选择"，选择队伍按钮）
    ↓
E_MarkTeamN（DispatchLogAction mode:"mark"，记录当前部队编号）
    ↓
E_UseTeamRecordN（使用部队记录，恢复该部队预设编队）                 ← 仅在长期远征计划开启时插入
    ↓

    ├── 全部 ≥ 阈值 → E_StartExpedition → ...（正常远征派遣）
    └── 有 < 阈值 的刀剑
        ↓
        │  刷花循环（持续循环，直到最低疲劳 > 阈值）
        │  ┌──────────────────────────────────────────────────────────────┐
        │  │ E_FlowerNavigate（右上角目录 → 出阵 → 1-1）                    │
        │  │     ↓                                                        │
        │  │ E_FlowerTeamSelectN（选择当前远征部队）                         │
        │  │     ↓                                                        │
        │  │ E_FlowerCheckCaptain（确认升序 → OCR 首位疲劳）                 │
        │  │     ├── 最低疲劳 > 阈值 → 跳出循环                             │
        │  │     └── 最低疲劳 ≤ 阈值                                        │
        │  │          ↓                                                    │
        │  │     E_FlowerDissolve（逐个叉掉 2-6 号位，仅保留队长）         │
        │  │          ↓                                                    │
        │  │     E_FlowerCaptain（特供换队长：交换旧队长）                  │
        │  │          ↓                                                    │
        │  │     E_FlowerSortie（点击出阵）                                  │
        │  │          ↓                                                    │
        │  │     E_FlowerBattleHub（战斗主枢纽，循环检测直至回本丸）          │
        │  │          │                                                    │
        │  │          ├── 行军/阵形/结果/掉落/远征弹窗/闪退 → 处理后回枢纽   │
        │  │          └── 本丸检测命中 → E_FlowerNavigate（重新导航出阵）    │
        │  └──────────────────────────────────────────────────────────────┘
        ↓
E_FlowerDone（全部刷完）
```

**关键链路**：开启长期远征计划后，`E_CheckTeamN` → `E_SelectTeamN` → ... → `E_ConfirmDispatchN` → `E_SelectTeamBtnN` → `E_MarkTeamN` 沿用现有远征管线节点不变。在 `E_MarkTeamN` 之后插入 `E_UseTeamRecordN`（使用部队记录恢复预设编队），然后进入 `E_CheckFatigueN`。全部合格时 `next` 走 `E_StartExpedition`。

**E_MarkTeamN**（`DispatchLogAction`）：MATR 内部日志记录，标记当前正在处理哪个部队。

## 关键设计决策

### 循环终止条件：最低疲劳值 > 用户阈值

> 注：游戏中的"疲劳值"实际是心情值，数值越高越好（高 = 心情好，低 = 疲惫）。

不预计算轮数。每轮选择部队后、解散前，确认升序排列并 OCR 首位（疲劳值最低，即最疲惫）刀剑的数值：

- 最低值 > 阈值 → 所有刀剑心情良好，该部队刷花完成，跳出循环
- 最低值 ≤ 阈值 → 存在需要休息的刀剑，进入解散→换队长→出阵流程

优势：不受 OCR 单次误差影响，循环中持续矫正；阈值由用户自定义，灵活适配不同需求。

### 特供换队长：喜爱筛选 + 颜色匹配

刷花链路中的换队长不沿用全局「换队长方式」（马匹/刀装/拖拽），使用独立的专用流程。该流程在 `E_FlowerDissolve` 解散队伍后直接调用，不再依赖游戏内置的部队记录来恢复编队。

1. `E_FlowerDissolve` 子链路逐个叉掉 2-6 号位刀剑，仅剩 1 号位（旧队长）
2. 点击"喜爱"标签进入喜爱筛选页面
3. 对「决定」按钮所在的整列（纵向长条区域）进行 ColorMatch
4. 取所有命中像素中最高处的那个，点击选中——该刀剑与 1 号位旧队长**交换位置**（新刀剑可能是仓库刀或其它部队成员）
5. 交换后新刀剑在 1 号位，旧队长移至新刀剑原本位置，2 号位依旧为空
6. 1-1 单骑出阵
7. 如果整列均未命中，上滑翻页后重新 ColorMatch

与普通换队长的差异：

- 普通换队长：按马匹/刀装排序 → 直接点疲劳最低的刀剑 → 拖拽到队长位
- 特供换队长：叉掉 2-6 号位 → 仅剩旧队长 → 喜爱筛选 → ColorMatch 找刀剑与 1 号位交换

### 为什么叉掉 2-6 号位后交换队长而非使用部队记录

叉掉 2-6 号位后队伍只剩旧队长一人，不通过部队记录恢复编队，而是用特供换队长交换当前队长。原因：

- 特供换队长通过喜爱筛选 + ColorMatch 找到可用刀剑，与 1 号位旧队长交换位置（新刀剑可能是仓库刀或其它部队成员）
- 交换后新刀剑在 1 号位，旧队长移至新刀剑原本位置，2 号位依旧为空，1-1 单骑出阵
- 不依赖部队记录，流程简洁且状态明确

### 刷花完成后的处理

刷花循环结束后，该队伍已处于编好队可出阵的状态。通过目录回到本丸，继续远征派遣链路（`E_StartExpedition`）。

### 战斗流程复用

从出阵点击到回到本丸的整个战斗链路（行军检测、阵形选择、战斗结果点击等），从 `Sortie.json` 或 `FlowerBrush.json` 中复制关键节点到 `Expedition.json`，前缀使用 `E_Flower`。不需要检非、重伤检测等复杂逻辑——1-1 不会遇到检非，且疲劳刷花时即使轻伤也无所谓。

## 所需节点清单

### 派遣前节点（每个部队一组，N=1~5）

以下节点中，`E_CheckTeamN` 到 `E_ConfirmDispatchN` 为现有远征管线节点，开箱即用无需新增。

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_CheckTeamN` | OCR | 现有节点，OCR "机"/"队员" 判断该部队是否待机 |
| `E_SelectTeamN` ~ `E_ConfirmDispatchN` | 现有链路 | 选队 → 验证界面 → 选地图 → 确认派遣，复用现有远征管线 |
| `E_SelectTeamBtnN` | OCR + Click | 现有节点，OCR "部队选择" 并点击，`next` → `E_MarkTeamN` |
| `E_MarkTeamN` | 自定义动作 | `DispatchLogAction mode:"mark" team:N`，记录当前部队编号 |
| `E_UseTeamRecordN` | Click | **新增**，点击游戏内置的"部队记录"按钮恢复预设编队（按钮位置由部队编号 N 决定，共 5 个节点）。`next` → `E_CheckFatigueN` |

### 疲劳检测节点（每个部队一组，N=1~5）

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_CheckFatigueN` | OCR × 6 位置 | 复用 DragCaptainAction 的 FatigueRois，读六个位置疲劳值与阈值比较。全部 ≥ 阈值 → `E_StartExpedition`；有 < 阈值 → 进入刷花循环 |

### 导航节点

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerNavigate` | 点击链路 | 右上角目录 → 出阵 → 点选維新 → 点选函館（1-1）。战斗回本丸后也通过此节点重新导航 |
| `E_FlowerTeamSelectN` | Click | 点击对应部队按钮 |

### 刷花链路节点

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerCheckCaptain` | OCR | 选择部队后、解散前执行。确认升序排列 → OCR 首位（疲劳最低）刀剑的疲劳值。> 阈值则跳出循环，≤ 阈值则进入解散→换队长→出阵流程 |
| `E_FlowerSortie` | Click | 点击出阵按钮 |

#### E_FlowerDissolve 子链路（逐个叉掉 2-6 号位）

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerDissolve` | 路由 | 枢纽节点，`next` 列表含 `E_FlowerDissolve_2` ~ `E_FlowerDissolve_6`、`E_FlowerDissolveDone` |
| `E_FlowerDissolve_2` ~ `E_FlowerDissolve_6` | 模板匹配 | 各位置分别检测是否有刀剑（模板匹配刀剑图标或 OCR 刀剑名称），命中则点击该位置的叉号按钮，`next` 回 `E_FlowerDissolve`；未命中（空位）则 `on_error` 回 `E_FlowerDissolve` 继续检查下一位置 |
| `E_FlowerDissolveDone` | DirectHit | 所有位置检查完毕后命中，`next` → `E_FlowerCaptain` |

#### E_FlowerCaptain 子链路（特供换队长）

顺序链式结构，非枢纽。流程为：点击喜爱 → ColorMatch 找按钮 → 未命中则上滑翻页重试，命中则完成。

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_FlowerCaptain` | 路由 | 入口节点，`next` → `E_FlowerCaptainClickFav` |
| `E_FlowerCaptainClickFav` | Click | 在刀剑筛选页点击"喜爱"标签，`next` → `E_FlowerCaptainFind` |
| `E_FlowerCaptainFind` | ColorMatch | 对「决定」按钮所在纵向长条区域进行 ColorMatch，取最高处命中像素点击——该刀剑与 1 号位旧队长**交换位置**，`next` → `E_FlowerCaptainDone`；未命中则 `on_error` → `E_FlowerCaptainSwipe` |
| `E_FlowerCaptainSwipe` | Swipe | 上滑翻页，`next` → `E_FlowerCaptainFind`（重新 ColorMatch） |
| `E_FlowerCaptainDone` | DirectHit | 换队长完成标记，`next` → `E_FlowerSortie` |

### 刷花战斗主枢纽

刷花出阵后的战斗阶段不能使用顺序节点链（行军→阵形→结果→回本丸），因为战斗中途可能发生闪退、远征完成弹窗、刀剑掉落等打断事件。必须使用检测枢纽模式。

`E_FlowerBattleHub` 作为刷花战斗阶段的主枢纽，next 列表覆盖以下场景：

| 分类 | 节点 | 说明 |
|------|------|------|
| 闪退恢复 | `E_IsAnnouncementPopup` | 公告弹窗 |
| 闪退恢复 | `E_IsLoginReward` | 登录奖励 |
| 闪退恢复 | `E_IsGameIcon` | 游戏图标（未启动） |
| 闪退恢复 | `E_IsLoginButton` | 登录按钮 |
| 闪退恢复 | `E_IsGameUpdatePopup` | 游戏更新弹窗 |
| 闪退恢复 | `E_IsInGameUpdatePopup` | 游戏内更新弹窗 |
| 闪退恢复 | `E_IsInternalReport` | 内番报告 |
| 远征结果 | `E_ClickExpeditionReturn_Exp` | 远征结果（经验） |
| 远征结果 | `E_ClickExpeditionReturn_Title` | 远征结果（标题） |
| 刀剑掉落 | `E_IsSwordDropColor` | 刀剑掉落 / 内番完成 |
| 战斗流程 | `E_FlowerMarching` | 行军画面 |
| 战斗流程 | `E_FlowerFormation` | 阵形选择（默认逆行阵） |
| 战斗流程 | `E_FlowerBattleResult` | 战斗结果点击 |
| 本丸 | `E_CheckHomeBrightness` | 本丸亮度检测 |
| 兜底 | `E_FallbackWait` | 等待后重试 |

**各节点命中后的路由**：
- 闪退恢复节点（`E_IsGameIcon` / `E_IsLoginButton` 等）→ 恢复后回到 `E_FlowerBattleHub`
- 远征结果节点 → 点击关闭后回到 `E_FlowerBattleHub`
- `E_IsSwordDropColor` → 点击关闭后回到 `E_FlowerBattleHub`
- `E_FlowerMarching` → `DoNothing` → 回到 `E_FlowerBattleHub`
- `E_FlowerFormation` → 点击阵形 → 回到 `E_FlowerBattleHub`
- `E_FlowerBattleResult` → 点击关闭 → 回到 `E_FlowerBattleHub`
- `E_CheckHomeBrightness` → 命中说明已回本丸 → `E_FlowerNavigate`（右上角目录 → 出阵 → 1-1，开始下一轮）
- `E_FallbackWait` → `DoNothing` → 回到 `E_FlowerBattleHub`

以下为需要 C# 实现的自定义动作。`E_FlowerDissolve`、`E_FlowerCaptain`、`E_UseTeamRecordN` 均为管线多节点链路，无需自定义动作。

## 与现有系统的交互

### 与远征智能调度的关系

两个全局开关独立工作，互不冲突：

- 长期远征计划：控制**派遣前**是否检查疲劳 + 刷花
- 远征智能调度：控制**派遣后**是否 OCR 剩余时间动态计时

都开启时流程为：
```
检查疲劳 → （如需刷花）→ 刷花完成 → 派遣远征 → OCR 剩余时间 → 智能计时
```

### 与同步远征的关系

长期远征计划在远征流水线中触发，因此同步远征（合战场/陆联/地下城勾选同步远征）自然也会受益——回本丸检查远征时会经过疲劳检查 → 刷花 → 派遣。

## 风险与边界情况

1. **刷花过程中游戏闪退**：`E_FlowerBattleHub` 内置了完整的闪退恢复节点链（`E_IsGameIcon`、`E_IsLoginButton`、`E_IsGameUpdatePopup`、`E_IsInGameUpdatePopup`、`E_IsAnnouncementPopup`、`E_IsLoginReward`），闪退后自动点击恢复并重新进入战斗枢纽循环。`FlowerStateTracker` 使用 static 变量，进程内不丢失，闪退恢复后可继续。`E_FlowerBattleHub` 同时设有 `timeout: 120000` + `on_error → E_RestartGame` 兜底。

2. **无限循环保护**：极端情况下疲劳值卡在某个非 100 的值（如刀剑已满级），设置最大循环上限 30 轮，超过则放弃刷花继续远征。

3. **部队为空**：如果远征队伍没有编入刀剑（全部空槽位），`E_CheckFatigueN` 返回"无可用位置"，直接跳过进入远征派遣。

4. **多队伍串行**：五个部队依次检查，队伍一的刷花完成后通过目录回到本丸，继续检查队伍二。

### 九、自定义动作实现细节

#### 9.1 FatigueCheckAction

两套疲劳 ROI，通过 `mode` 参数切换：

```csharp
// 远征队伍面板（mode: "check_all"）
private static readonly int[][] FatigueRoisExpedition =
[
    [839, 190, 77, 22], // 位置一
    [839, 284, 77, 22], // 位置二
    [839, 379, 77, 22], // 位置三
    [839, 473, 77, 22], // 位置四
    [839, 568, 77, 22], // 位置五
    [839, 662, 77, 22], // 位置六
];

// 出阵编队页面（mode: "check_captain"）
private static readonly int[][] FatigueRoisSortie =
[
    [340, 187, 80, 22], // 位置一
    [340, 282, 80, 22], // 位置二
    [340, 376, 80, 22], // 位置三
    [340, 471, 80, 22], // 位置四
    [340, 565, 80, 22], // 位置五
    [340, 660, 80, 22], // 位置六
];
```

- `check_all` 模式检查全部六个位置（远征面板），最低值 ≤ 阈值则 `results.Status = false`
- `check_captain` 模式仅检查首位（出阵编队页，确认升序已完成），`results.Status` 反映是否 > 阈值
- 阈值来源：全局选项「疲劳阈值」→ 默认 91

#### 9.2 FlowerStateTracker

```csharp
public static class FlowerStateTracker
{
    public static int TargetTeam { get; set; }  // 当前刷花目标部队编号
    public static int LoopCount { get; set; }   // 当前刷花循环轮数
    public static int CurrentFatigueLowest { get; set; }  // 最近一次检测的最低疲劳值
    public const int MaxLoops = 30;             // 最大循环轮数

    public static void Reset() { TargetTeam = 0; LoopCount = 0; CurrentFatigueLowest = 0; }
    public static bool IsMaxLoopsExceeded() => LoopCount >= MaxLoops;
}
```

### 十、pipeline_override 注入逻辑

当「长期远征计划」全局开关开启时，需要在 `MaaProcessor` 中注入以下 pipeline_override：

| 注入目标 | 内容 |
|----------|------|
| `E_MarkTeamN.next` | 从 `E_StartExpedition` 改为 `E_UseTeamRecordN` |
| `E_UseTeamRecordN.next` | → `E_CheckFatigueN` |
| `E_CheckFatigueN` 节点的 `custom_action_param` | 注入 `threshold` 值（来自全局选项） |

关闭开关时恢复原链路（`E_MarkTeamN.next` → `E_StartExpedition`）。

### 十一、全局选项 GUI

需在 `interface.json` 的 `global_option` 数组和 `option` 对象中添加：

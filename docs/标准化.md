# 项目结构标准化方案

## 目标

将 MATR 的目录布局回到 MFAAvalonia 上游原生标准，不再自行定制路径，从而可以直接同步上游更新，不再需要维护 fork 分支。

## 当前布局（非标准，之前自行修改过）

```
MATR/
├── MATR.exe
├── resource/
│   ├── interface.json        ← 塞在 resource 里面
│   ├── base/
│   │   ├── pipeline/
│   │   └── image/
│   ├── config/               ← 塞在 resource 里面
│   ├── temp/                 ← 塞在 resource 里面
│   └── backup/               ← 塞在 resource 里面
├── _src/                     ← 修改过的 MFAAvalonia 源码
├── debug/
│   └── logs/
```

## 目标布局（MFAAvalonia 上游标准）

```
MATR/
├── MATR.exe
├── interface.json            ← 提到根目录
├── resource/
│   └── base/
│       ├── pipeline/
│       └── image/
├── config/                   ← 从 resource/ 里提出来
│   └── instances/
├── agent/                    ← 从 resource/ 里提出来
├── temp/                     ← 从 resource/ 里提出来
├── backup/                   ← 从 resource/ 里提出来
├── _src/                     ← 回到上游 MFAAvalonia 原生代码
├── debug/
│   └── logs/                 ← 不动
```

## 变更清单

### 1. `_src/MFAAvalonia/Helper/AppPaths.cs`

所有属性回到上游 MFAAvalonia 原生写法。当前本地修改 → 目标：

| 属性 | 当前（MATR 修改） | 目标（上游原生） |
|------|-------------------|-----------------|
| `InterfaceJsonPath` | `resource/interface.json` | `interface.json` |
| `InterfaceJsoncPath` | `resource/interface.jsonc` | `interface.jsonc` |
| `ResourceDirectory` | `resource/` | `resource/`（不动） |
| `ConfigDirectory` | `resource/config/` | `config/` |
| `AgentDirectory` | `resource/agent/` | `agent/` |
| `TempDirectory` | `resource/temp/` | `temp/` |
| `BackupDirectory` | `resource/backup/` | `backup/` |
| `LogsDirectory` | `debug/logs/` | `debug/logs/`（不动） |

其余属性（`InstallRoot`、`DataRoot`、`GlobalConfigPath` 等）跟随上游。

### 2. `resource/interface.json`

文件物理位置从 `resource/interface.json` 移到根目录 `interface.json`。`resource` 配置中的 `{PROJECT_DIR}/resource/base` 路径不变。

### 3. `pack.ps1`

- `resource/` → `$TempDir/resource/`（不含 `interface.json`、`config/`、`temp/`、`backup/`）
- `resource/interface.json` → `$TempDir/interface.json`
- `resource/config/` 的内容 → 改为输出运行时默认生成的目录，不打包
- 其余文件（MATR.exe、DLL、runtimes、debug/logs 等）不变

### 4. 项目根目录

- 将 `resource/interface.json` 复制到根目录
- 创建或迁移 `config/`、`agent/`、`temp/`、`backup/` 目录
- `resource/config/`、`resource/temp/`、`resource/backup/` 可在验证后清理

## 开发目录 vs 发布目录

开发时和发布后目录结构保持一致，不再有差异。

## 不变的部分

- `resource/base/pipeline/` + `resource/base/image/` — 流水线核心资源不动
- `debug/` — 日志和调试截图
- `_src/` 其余代码 → 后续逐步回到上游
- 用户数据（`config/` 下的实例配置等）——迁移到新位置即可

## 执行顺序

1. ~~备份当前项目~~ 已完成
2. 将 `resource/interface.json` 复制到根目录
3. 创建 `config/`、`agent/`、`temp/`、`backup/` 空目录
4. 将 `AppPaths.cs` 回到上游原生版本
5. 将 `pack.ps1` 适配新布局
6. 编译测试
7. 打包验证
8. 清理旧目录（`resource/config/`、`resource/temp/`、`resource/backup/`）

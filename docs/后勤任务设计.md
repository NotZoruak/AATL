# 后勤任务设计

## 概述

- 流水线文件：`assets/resource/base/pipeline/Expedition.json`（复用远征流水线，node 前缀延续 `E_`）
- 任务更名：远征 → 后勤（entry 保持 `Expedition` 不变，兼容已有配置）
- 功能组成：远征（原有）+ 修刀（新增）+ 内番（新增，全忙后检查「待机中」并指派）
- 核心思想：修刀与内番均视为「多 N 个位置的远征」——与远征派遣行为模式一致，检查到空闲位置即处理，处理完回本丸继续循环
- 时间控制约定：点击类 node 统一使用 `post_wait_freezes` 替代 `pre_delay`/`post_delay` 硬延迟——点击后等待检测区域画面冻结，动画结束即通过，画面不变约 2 倍采样间隔后通过，不会卡死

## GUI 选项

| 选项 | 类型 | 说明 |
|------|------|------|
| 部队一～五 | select | 原有，每队选择远征地图 |
| 修刀 | switch | 新增，默认关闭；开启后显示修复工坊子选项 |
| 修复工坊一～四 | checkbox | 修刀子选项，默认关闭；开启后启用对应工坊检查 node 与修复槽位 node |
| 内番 | switch | 新增，默认关闭；开启后启用内番检查（`E_NaibanHub`） |
| RefreshInterval | input | 原有，刷新间隔秒数（置于最底部） |

```json
{
    "name": "后勤",
    "entry": "Expedition",
    "default_check": true,
    "repeatable": false,
    "option": ["部队一", "部队二", "部队三", "部队四", "部队五", "修刀", "内番", "RefreshInterval"]
}
```

「修刀」switch 的 Yes case 挂子选项 `option: ["修复工坊一", "修复工坊二", "修复工坊三", "修复工坊四"]`（参照「长期远征计划」的 `option: ["疲劳阈值"]` 模式）。

修复工坊选项通过 `pipeline_override` 控制 node 的 `enabled`：
- 未勾选（默认）：`E_CheckWorkshopN.enabled: false` / `E_SelectRepairSlotN.enabled: false`，检查链直接跳过，行为与纯远征一致
- 勾选：同时启用 `E_CheckWorkshopN`（状况面板工坊检查）与 `E_SelectRepairSlotN`（修复界面槽位选择）

「内番」switch 通过 `pipeline_override` 控制 `E_NaibanHub.enabled`：
- 关闭（默认）：`E_NaibanHub.enabled: false`，工坊检查链结束后直接 `E_AllTeamsBusy`，不检查内番
- 开启：`E_NaibanHub.enabled: true`，工坊检查链结束后进入内番检查与指派

### 同步远征 → 同步后勤

- 合战场（`S_同步远征`）、地下城（`U_同步远征`）、陆联（`LR_同步远征`）、战术强化（`TT_同步远征`）四个选项的 label 由「同步远征」改为「同步后勤」
- 内部 name 保持不变（选项值按 name 持久化，改名会导致用户勾选状态丢失）
- 各任务描述中的「同步远征」文案同步改为「同步后勤」
- 同步后勤合并的后勤配置：部队一～五、修刀 switch 及修复工坊子选项、**内番 switch**、RefreshInterval（`MaaProcessor.CreateNodeAndParam` 的 `ProcessOptions` 逐项合并；内番开关缺失会导致其他任务执行后勤检查链时 `E_NaibanHub` 保持禁用、内番检查被静默跳过）

### 派遣链失败重试闭环

```
E_SelectTeamN（点本丸远征 + 200ms freeze）
  → E_VerifyScreenN（OCR 远征目的地选择）
  │  命中 → E_SelectMapN → E_ClickSmallMapN → E_ConfirmDispatchN（点派遣 + 100ms freeze）
  │        → E_SelectTeamBtnN（OCR 部队选择）→ E_MarkTeamN → E_StartExpedition → 派遣确认
  │        → 未命中「部队选择」→ 候选 E_VerifyScreenN 兜底（仍在目的地选择 → 重走地图链路）
  │  未命中 → E_SelectTeamN 自回重试（候选列表 next[1]）
```

- `E_VerifyScreenN.next` 仅含 `E_SelectMapN`：命中后 DirectHit 执行点地图；未命中时作为候选被跳过，由 `E_SelectTeamN` 的 next[1] 自回承接，`E_SelectMapN` 不会在错误画面上执行
- `E_ConfirmDispatchN.next` 含 `E_SelectTeamBtnN` 与 `E_VerifyScreenN` 双候选：派遣按钮点击后若「部队选择」弹窗未出现，回 `E_VerifyScreenN` 确认仍在地图界面则重走链路
- 时间控制：`E_SelectTeamN` 200ms / `E_SelectMapN`·`E_ClickSmallMapN`·`E_ConfirmDispatchN`·`E_StartExpedition` 100ms（全屏或显式 roi [0,0,1280,720]）·`E_ConfirmExpedition` 200ms

## 检查链设计（全忙后）

五队全忙时进入工坊检查链，模式与 `E_ExpSubHub` 相同（disabled 只出现在 next[0]，next[1] 均为 enabled 枢纽）：

```
E_ExpSubHub5 全忙 → E_WorkshopHub → [E_CheckWorkshop1 → E_WorkshopHub2]
  → [E_CheckWorkshop2 → E_WorkshopHub3] → [E_CheckWorkshop3 → E_WorkshopHub4]
  → [E_CheckWorkshop4 → E_NaibanHub] → E_NaibanCheck → E_AllTeamsBusy
```

工坊全部使用中（或未勾选任何工坊）时进入内番检查。`E_WorkshopHub4` 与 `E_CheckWorkshop4` 的 next[1] 均指向 `E_NaibanHub`。

| node | 识别 | 说明 |
|------|------|------|
| `E_CheckWorkshopN`（N=1..4） | OCR「未使用」 | 状况面板工坊位置，ROI：[1039,37,81,35] / [1039,98,81,34] / [1038,158,82,36] / [1036,221,83,37]；空闲 → 修复流程，否则 → 下一工坊 |
| `E_ClickRepairButton` | TemplateMatch `Common/本丸修复.png` | 修复按钮（roi [1221,47,36,100]），命中点击 + 200ms freeze；未命中自回重试 |
| `E_VerifyRepairScreen` | OCR「修复状况」 | 修复状况页确认（roi [553,62,172,38]）；未命中回点击 node |

## 修复流程（点击空槽后）

```
E_VerifyRepairScreen 命中 → E_SelectRepairSlot1..4（多候选 next 路由）
  → 命中点击（模板 Common/未使用修刀槽.png，ROI：[307,163,255,89] / [303,300,255,90] / [304,432,255,90] / [304,565,255,90]）
    → E_VerifyRepairSelect（OCR「修复刀剑男士」[195,129,151,34]，仅确认页面，不点击）
      → E_FindRepairableSword（自定义动作 ClickTopRepairableSwordAction）
        → E_ConfirmRepair（OCR「修复」[1156,587,85,44]，命中点击）
          → E_GoHome
```

- 槽位 node 默认 disabled，由「修复工坊N」选项联动启用
- 槽位未命中 → 自回重试；验证页未命中 → 回槽位；确认页未命中 → 回验证页
- 各 node `on_error → E_GoHome`
- 不使用加速符（确认修复直接点击）

### 选刀：颜色识别 + 长按滑动

`E_FindRepairableSword` 使用自定义动作 `ClickTopRepairableSwordAction`（`_src/MFAAvalonia/Extensions/MaaFW/Custom/`）：

- 在 [459,127,16,554] 区域扫描白色标记像素（RGB 252~255，可修复刀剑的标记；出阵中的刀剑无白色标记，避免误修出阵任务使用的刀）
- 取最上方白色区域中心点击；当前视野未找到时按三段式长按滑动继续查找：按住 [732,638] 0.5s → 800ms 滑动到 [732,131] → 再按住 1s
- 最多滑动 8 次，仍找不到 → 回本丸（不修）
- 参数均可经 `custom_action_param` 覆盖（roi/lower/upper/max_swipes/swipe_from/swipe_to/press_hold_ms/swipe_duration/release_hold_ms）
- 日志仅写入日志文件，不输出 GUI

## 内番指派流程

状况面板 OCR「待机中」命中后进入指派链（全程 `E_Naiban` 前缀）：

```
E_NaibanCheck（OCR「待机中」[915,297,296,43]）
  → E_NaibanClickEntry（TemplateMatch 本丸内番.png ROI [1220,315,40,106]，命中点击，面板不关闭，200ms freeze）
  → E_NaibanVerifyTable（OCR「今日内番表」[554,7,177,42]，命中后直接点 [1149,585,98,89] 开始内番，200ms freeze）
  → E_NaibanVerifyConfirm（OCR「内番设置确认」[541,55,196,41]，命中后直接点 [725,588,125,40] 确认，200ms freeze）
  → E_GoHome
```

| node | 识别/动作 | 未命中走向 | on_error 走向 |
|------|-----------|------------|---------------|
| `E_NaibanHub` | 路由枢纽（默认 enabled: false） | — | `E_AllTeamsBusy` |
| `E_NaibanCheck` | OCR「待机中」[915,297,296,43] | 「内番中」→ `E_AllTeamsBusy` 回本丸 | `E_AllTeamsBusy` |
| `E_NaibanClickEntry` | 本丸内番.png ROI [1220,315,40,106]，点击 + 200ms freeze | 自回重试 | `E_AllTeamsBusy` |
| `E_NaibanVerifyTable` | OCR「今日内番表」，命中点 [1149,585,98,89] 开始内番 + 200ms freeze | 自回重试 | `E_NaibanClickEntry` 重试点入口 |
| `E_NaibanVerifyConfirm` | OCR「内番设置确认」，命中点 [725,588,125,40] 确认 + 200ms freeze | 自回重试 | `E_GoHome` |

- 队伍状况面板开启状态下即可识别「本丸内番」按钮并点击，无需关闭面板
- 指派链 node 均不使用 pre/post_delay，时序由 `post_wait_freezes` 控制
- `E_NaibanVerifyConfirm` 确认后接 `E_GoHome`：确认弹窗关闭后若停留在今日内番表则走「点目→菜单→回本丸」，若已回本丸则走 `E_LeaveTroopRecord` 兜底回枢纽
- 指派完成后的剩余时间文本会出现在状况面板同一位置（「内番中（XX:YY:ZZ）」），下轮循环 OCR 该文本不再命中「待机中」，不会重复指派

## 回本丸流程（E_GoHome）

```
E_GoHome → E_ClickDirectoryTop（OCR「目」[1183,18,87,40]，命中点击 + 200ms freeze）
  → E_PostClickDirectoryHub → E_VerifyMenuDir（TemplateMatch 菜单目录.png ROI [581,28,112,57] + 200ms freeze [0,631,137,89]）
  → E_ClickBackToHome（点 [1037,169,110,44] + 200ms freeze [0,631,137,89]）→ E_WaitRefresh → 枢纽
```

- `E_PostClickDirectoryHub` 菜单验证失败 → `E_GoHome` 重试回本丸流程（`E_CheckNavDirRetry_Exp` 已删除）
- 本丸画面（无「目」按钮）时 `E_ClickDirectoryTop` 未命中 → `E_LeaveTroopRecord`（部队记录页模板，命中点关闭）→ 枢纽
- `E_VerifyLeftMenu` 同为菜单验证 node（on_error → `E_WaitRefresh`），与 `E_VerifyMenuDir` 覆盖不同调用路径

## 重复路由约定

- 当主枢纽（`Expedition` / `*_DetectWhereAmI`）已经位于某 node 的 `next` 列表中时，该 node 的 `on_error` 不再指回主枢纽——识别未命中时 next 候选已含枢纽兜底，on_error 重复指向属于冗余（MaaFW 插件 `duplicate-next` 校验）
- 全项目已清理 257 处此类 on_error；无识别的纯动作 node（DirectHit 必中）放在 next 末尾的候选永远不会被轮到，设计 next 时将其置于首位或删除
- `DoNothing` action 为 MaaFW 默认值，显式书写可省略（全项目已清理 74 处）

## 智能调度扩展

- 全局选项「远征智能调度」开启时：`E_TrackerOCR`（`ExpeditionTimeTracker`）识别远征剩余时间，取 `min(刷新间隔, 远征剩余)` 决定刷新等待

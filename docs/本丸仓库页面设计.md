# 本丸页面设计

## 状态

页面设计与实现记录。当前已确定「本丸」入口和三个固定下级页面，工作记录页面已完成首版，仓库页面已完成资源识别、手动编辑、历史保存与趋势图首版。

## 设计目标

“本丸”是小白的动态数据中心，用于查看随用户使用持续产生的本丸数据、工作记录和刀帐信息。

它与数据库的职责不同：

- 数据库保存静态资料，例如刀剑基础数据、地图数据和远征数据。
- 本丸存放用户实际运行后产生的动态数据，并保存在本地。
- 本丸中的数据由用户主动更新，或由运行日志解析产生。

## 页面结构

侧边栏新增“本丸”入口，下设三个固定顺序的页面：

1. 仓库
2. 工作记录
3. 刀帐

三个页面使用页签切换，不支持用户拖动调整顺序。

三个页面分别回答：

- 仓库：现在有什么，资源如何变化？
- 工作记录：小白做了什么，执行结果如何？
- 刀帐：有哪些刀剑，当前状态如何？

本丸页面使用紧凑的页签布局。进入本丸后不再重复显示“本丸”大标题，直接显示三个页签；进入工作记录后也不重复显示“工作记录”大标题。

## 仓库

### 数据来源

用户点击页面上的“自动识别”后，小白读取当前本丸画面中的资源和状态，生成一份本地数据快照草稿。识别完成后，用户需要手动点击“保存”，数据才会正式写入本地仓库数据。

更新不会覆盖历史快照，而是追加一条带时间的记录，用于后续趋势展示。

自动识别流程要求用户在游戏中打开能够看到右上角目录入口的页面即可，具体流程由小白自动完成：

1. 打开目录并进入锻刀页面。
2. 识别木炭、玉钢、冷却材、砥石和委托符。
3. 通过目录进入所持道具页面。
4. 识别小判及其他物品，并按游戏页面中的左到右、上到下顺序记录。
5. 上滑物品列表，重复识别，直到连续三次识别结果相同。
6. 将识别结果填入页面编辑区，等待用户确认保存。

自动识别期间不会直接刷新正式历史记录，也不会自动刷新趋势图。

### 展示内容

- 当前核心资源数量：木炭、玉钢、冷却材、砥石、委托符、加速符和小判。
- 其他道具数量。
- 核心资源历史快照及趋势图。
- 最近一次保存时间。

页面上方为核心资源区，核心资源使用紧凑的横向布局：木炭、玉钢、冷却材和砥石显示图标；委托符、加速符和小判使用文字标签。输入框根据资源的可使用上限自适应宽度，既能完整显示数字，也不会让小数值资源占用过多空间。

页面下方分为左右两个区域：

- 左侧为其他物品列表，列表独立滚动。
- 右侧为核心资源变化图表，图表区域独立滚动。

核心资源变化和其他物品两个标题使用灰色小字，避免与页面主要操作和资源数值争夺视觉重点。没有数据时，列表或图表区域显示简洁的空状态提示。

折线图只使用已经保存的历史快照，不使用尚未保存的自动识别草稿。每种核心资源单独显示一张纵向排列的图表，并且每个历史快照对应一个圆点。

- 横轴按照快照的实际记录时间进行线性映射，时间间隔越长，点之间的横向距离越大。
- 当所有记录时间相同时，退回均匀分布，避免点重叠在同一位置。
- 每种资源独立计算纵轴范围，避免小数值资源被大数值资源压扁。
- 图表会显示当前值、历史最小值和历史最大值。
- 鼠标悬停在圆点上时显示记录时间和资源数量。
- 右键圆点可以删除该资源在该时间点的记录，不影响同一时间点的其他资源。
- 图表区域提供“刷新图表”和“清空”按钮；清空需要二次确认。
- 删除和清空只修改当前编辑数据，仍需点击页面上方“保存”才会正式写入本地数据。

### 更新与保存

“自动识别”和“保存”是两个不同概念：

- 自动识别：从当前游戏画面读取最新状态并生成待确认快照。
- 保存：将当前编辑区的资源和道具数据写入正式本地数据，并追加核心资源历史快照。
- 撤销：放弃当前尚未保存的手动修改或识别结果。
- 清空：清空当前编辑数据；危险操作需要确认。

自动识别不允许覆盖用户尚未保存的编辑内容。保存后才允许通过“刷新图表”查看新历史点。

## 工作记录

### 定位

工作记录页面不是原始日志查看器，而是对原始日志中的 MaaFW 识别记录进行解析后得到的运行报告。

当前已经实现基础解析流程：

```text
原始日志
→ 识别记录
→ 任务过程
→ 运行统计
→ 页面卡片
```

日志解析代码位于 `MFAAvalonia.Services`，页面通过 ViewModel 触发刷新并重建运行记录列表。

### 原始数据提取

解析器直接读取 `debug/logs` 下的原始日志，提取：

- 时间
- 任务名称
- 识别步骤名称
- 识别成功或失败
- 动作执行结果
- 相关文字或模板名称

解析器先保留识别事实，再根据任务流程组合出运行过程，最后生成页面统计。页面不直接依赖某一句日志文案作为最终业务结论。

工作记录原始日志默认保留最近 30 天，过期日志由自动清理逻辑处理。页面顶部显示相对存放位置 `debug/logs` 和清理期限。

### 页面布局

页面由“时间—任务”列表和统计卡片组成，整体采用左右两列卡片布局：左侧为记录列表，右侧为当前记录详情。

左侧为运行记录列表，每一行表示一段任务运行时间：

```text
开始时间—结束时间    任务名称
```

例如：

```text
08-19 07:30—08:16    日课
08-19 09:10—10:42    地下城
08-19 12:00—12:35    合战场
```

用户选中一条记录后，右侧显示该时间段的运行统计卡片。

左侧记录列表卡片标题行右侧提供“刷新记录”按钮。列表支持滚动，选中记录使用主题色的浅色背景和左侧指示条表示，普通记录保持低对比度，避免长列表产生强烈色块干扰。

### 统计卡片

#### 任务概况

- 任务名称
- 开始时间
- 结束时间
- 总耗时
- 运行结果
- 出阵次数
- 行军次数
- 完成圈数
- 刷花次数（有记录时显示）
- 返回本丸次数（大于 0 时显示）

#### 出阵统计

出阵统计已经并入“任务概况”卡片，当前展示：

- 出阵次数
- 行军次数
- 完成圈数
- 刷花次数
- 返回本丸次数

其中刷花次数和返回本丸次数为 0 时隐藏，避免空统计占用空间。

#### 任务收获

任务收获卡片仅在存在内容时显示，资源收获和刀剑掉落放在同一张卡片中：

- 资源收获以一排文本展示，使用资源主题色
- 刀剑掉落按刀种分组，每个刀种单独一行
- 刀种加粗显示，刀名和数量使用统一的紧凑格式
- 资源收获与刀剑掉落之间保留额外间距，便于区分两类内容

#### 后勤记录

后勤记录的分类依据是“产生记录的任务类型”，不是行为名称本身。

以下内容由后勤任务或其他任务中的同步后勤产生时，归入“后勤记录”：

- 远征检查、收取和派遣
- 修刀
- 内番安排
- 刷花
- 补充刀装

当前后勤卡片仅在有内容时显示。`检查队伍状况` 与后勤 `刷花` 会在同一行展示，以减少重复占用；其他后勤行为继续逐行展示。

出阵任务产生的刷花不归入后勤记录，而是在任务概况中显示为“刷花次数”。

如果相同行为是由出阵任务自身产生的，则不自动归入后勤记录。例如，地下城战斗受伤后触发的修刀，应归入地下城工作记录或特殊情况，而不是后勤记录。

#### 特殊情况

- 重伤撤退次数
- 刀装破坏撤退次数
- 补充刀装次数
- 任务异常停止次数
- 闪退恢复次数
- 卡死恢复次数
- 其他需要用户关注的中断和恢复

特殊情况卡片仅在有内容时显示。

### 刷新和数据保留

工作记录页面提供“刷新记录”操作。刷新时重新读取并解析当前日志，发现新的运行记录，但不自动改变本地归档状态。

当前版本的刷新操作会重新扫描 `debug/logs` 下的 `log-*.log` 文件，并按时间倒序重建记录列表。页面暂不提供单独的归档、批量保存和删除按钮。

原始日志由自动清理规则保留最近 30 天；页面解析失败时记录错误日志，并保留当前已有列表，避免页面因单个日志异常而不可用。

## 刀帐

刀帐页面用于集中查看刀剑相关信息。具体字段待后续根据现有数据源和用户需求确定，初步考虑包括：

- 已获得刀剑
- 未获得刀剑
- 等级
- 极化状态
- 当前疲劳状态
- 是否锁定
- 所属部队

刀帐页面与静态刀剑数据库需要区分：数据库提供基础资料，刀帐展示用户本丸中的实际持有和使用状态。

## 工作记录视觉风格

- 使用白色圆角卡片承载不同信息区块，空卡片不显示。
- 页面背景使用浅色中性底色，卡片使用清晰但克制的边框。
- 标题使用深蓝灰色，正文使用中性灰蓝色。
- 资源收获使用低饱和绿色，刀剑掉落使用蓝灰色，后勤和特殊情况使用中性文字。
- 选中记录、页签指示条和交互控件跟随用户自定义主题色，但记录本身不使用刺眼的高饱和色块。
- 同级文字保持统一字号，区块标题通过加粗和颜色层级区分，不依赖过大的正文文字。
- 记录列表与详情卡片共享紧凑的左右边距，顶部数据路径信息与卡片保持较小间距。

## 本地数据原则

- 仓库快照、其他物品数量和已保存的运行结果均保存在本地。
- 工作记录原始日志与解析后的结果分开保存；仓库数据不依赖工作记录日志。
- 仓库正式数据使用 `WarehouseData` 配置项保存，自动识别中间结果使用独立草稿文件保存。
- 原始日志和自动识别草稿都不替代正式数据，也不能因为页面刷新而覆盖正式数据。
- 过期工作记录日志清理由日志自动清理逻辑负责；用户主动保存的仓库快照不设置自动清理期限。
- 页面展示和图表刷新不应改变原始日志内容。

## 仓库功能完整设计

本节记录仓库页面的完整设计与当前实现约定，后续实现和调整以此为准。

### 功能目标

仓库页面用于记录玩家本丸中的资源和道具数量。它同时承担三个职责：

- 展示当前数量，方便快速确认资源状态。
- 通过自动识别减少手动录入工作。
- 保存带时间的资源快照，用折线图观察资源变化趋势。

仓库页面不负责展示刀剑持有情况。刀剑持有情况属于刀帐页面；仓库中的其他物品只记录名称和数量。

### 页面布局

页面顶部为统一操作区，包含四个按钮：

- “自动识别”：从当前游戏画面开始执行仓库识别流程。
- “保存”：保存当前编辑数据和待保存的历史快照。
- “撤销”：放弃当前尚未保存的修改。
- “清空”：清空当前仓库编辑数据，执行前需要确认。

操作按钮跟随统一视觉风格。自动识别使用主题色浅色按钮，保存使用绿色，撤销使用灰色，清空使用红色。自动识别运行期间按钮不可重复点击，并显示运行中状态。

操作区下方为核心资源卡片。核心资源卡片采用紧凑的自适应横向排列，根据可用宽度自动决定每行显示的数量，不能因为窗口宽度变化而裁切资源项。

核心资源分为两种展示方式：

- 木炭、玉钢、冷却材、砥石使用图标加数字输入框。
- 委托符、加速符、小判使用文字标签加数字输入框，不使用图标。

输入框宽度根据资源可使用上限和数字显示需要自适应：

- 木炭、玉钢、冷却材、砥石的上限为 `9999999`。
- 小判的上限为 `99999999`。
- 委托符、加速符的上限为 `9999`。

数字统一使用千位分隔显示，输入内容按非负整数处理。输入框文本左对齐，便于比较不同资源的数字长度。

核心资源卡片下方是左右分栏：

- 左侧为“其他资源”，宽度较窄，独立垂直滚动。
- 右侧为“核心资源变化”，宽度较宽，独立垂直滚动。

其他资源列表滚动到底部后提供“＋ 添加物品”按钮。用户可以新增一行物品名称和数量，用于补录 OCR 没有识别到的物品或记录尚未纳入识别词表的物品。

其他物品的数量设为 0 后立即隐藏该条目，并在下一次保存时从正式仓库数据中移除。自动识别得到数量 0 时也不创建或保留该物品条目。核心资源与其他物品不同，核心资源即使数量为 0 也始终显示。

右侧需要更多横向空间来显示时间轴和趋势线，因此分栏比例优先保证图表区域宽度。左右两张卡片顶部对齐；已保存记录等条件性区域隐藏时，允许页面下方不强制保持两侧高度一致。

“其他资源”和“核心资源变化”使用灰色小标题。列表或图表没有数据时，显示居中的低对比度空状态文字，不显示空白输入项或无意义图表。

### 数据模型

仓库正式数据通过配置键 `WarehouseData` 保存，数据结构包含三部分：

```text
WarehouseData
├─ CoreResources       当前核心资源数量
├─ OtherItems          当前其他物品名称与数量
└─ ResourceHistory     核心资源历史快照列表
   ├─ RecordedAt       快照记录时间
   └─ Values           本次快照中实际识别到的资源及数量
```

`ResourceHistory` 中每一条快照可以只包含部分核心资源。缺少某个资源的快照不应被补成 0，否则会把“本次没有记录”错误显示为“资源数量为 0”。

自动识别过程中先写入 `config/warehouse_scan.json` 临时草稿。草稿用于跨越识别流程保存中间结果，不能直接作为正式历史数据展示。只有用户点击“保存”后，草稿中的当前数量和历史快照才合并到 `WarehouseData`。

个人仓库数据属于用户数据，不应进入版本控制、发布压缩包或 Git 提交。打包脚本和提交规则必须继续忽略 `config/` 等运行时目录。

### 自动识别流程

用户开始前只需要保证当前游戏页面能看到右上角目录区域，不要求从某个固定的资源页开始。流程如下：

1. 识别右上角目录“目”，点击打开目录。
2. 识别并点击“锻刀”。
3. 识别“锻刀状况”，确认进入正确页面。
4. 依次读取木炭、玉钢、冷却材、砥石、委托符、加速符。
5. 再次识别并点击右上角目录“目”。
6. 识别并点击“所持”，进入所持道具页面。
7. 识别“所持道具一览”，读取页面右上角的小判数量。
8. 读取当前所持道具页的其他物品名称和数量。
9. 按游戏界面顺序上滑物品列表：从 `[656,567]` 按住，滑动到 `[656,177]`，滑动持续 500ms，并在滑动过程中保持按住状态。
10. 每次滑动后等待页面稳定并再次识别。只有识别到有效物品的页面才参与“连续未变化”判断；空页或页面切换中的不完整结果会重置计数。
11. 连续三次有效识别结果相同后，认为已经到达列表末尾并结束扫描。
12. 将识别结果写入临时草稿，并回填到仓库页面的编辑区。

识别结果的物品顺序按照游戏页面中的左到右、上到下排列。名称纠正必须在写入草稿前完成，避免同一物品因为 OCR 字符差异生成多个条目。例如，只要识别结果包含“月下梅树”，统一归一化为“锷·月下梅树透图碎片”。

如果用户曾经手动校对其他物品名称并保存，后续自动识别会优先使用最近正式保存数据中的物品名称进行匹配：

- 先尝试与已保存名称精确匹配。
- 再尝试与名称归一化后的结果匹配。
- 对距离足够接近的 OCR 结果使用已保存名称，避免 OCR 再次把已校对名称拆成新的条目。
- 无法安全匹配时，保留新的识别名称，避免错误合并不同物品。

每个识别 node 和自定义 action 都必须具备错误回退路径。目录点击后使用 200ms 冻结，避免页面切换尚未完成时继续识别。物品列表扫描由 `WarehouseScanItemsAction` 负责，每次滑动松手后等待 1 秒再进行 OCR 和到底判断，数量 OCR 结果需要去除逗号、单位和其他非数字字符后再转换为整数。

### 编辑、撤销与保存

用户可以直接编辑核心资源和其他物品数量，也可以在自动识别完成后修正 OCR 结果。所有修改先保存在页面编辑状态中：

- 数字必须在对应资源上限范围内。
- 其他物品名称允许编辑，但保存时应使用名称归一化规则。
- 自动识别结果不会自动覆盖用户当前未保存的手动编辑。
- “撤销”恢复到上一次正式保存的数据，并清除待保存历史快照。
- “保存”同时保存当前数量和待保存的核心资源历史快照。
- 未发生修改时，保存按钮不可用。
- 自动识别尚未完成时，保存按钮不可用。

一次完整自动识别完成后追加一条带 `RecordedAt` 的核心资源快照。快照只记录本次实际获取到的资源字段；其他物品当前只保存最新数量，不参与核心资源折线图。

### 核心资源折线图

右侧“核心资源变化”区域为每种核心资源显示一张独立折线图，图表按资源纵向排列，并由区域自己的滚动条承载较多资源图表。

图表只使用正式保存的 `ResourceHistory`，自动识别草稿不会立即出现在图表中。识别完成后，用户必须先点击页面顶部“保存”，再点击图表区域的“刷新图表”查看新数据。

每张图表的绘制规则如下：

- 每个有效历史快照显示一个圆点。
- 圆点的 X 坐标按照快照的实际 `RecordedAt` 时间线性映射，而不是按照记录数量均匀分布。
- 两条记录的时间间隔越长，圆点之间的横向距离越大。
- 图表左右保留固定边距，确保首尾圆点和折线不会被裁切。
- 若所有有效记录时间完全相同，则退回按记录顺序均匀排列。
- Y 坐标按当前资源自身的历史最小值和最大值计算，确保小数值资源和大数值资源都能看清变化。
- 当最小值和最大值相同时，使用最小安全范围，避免折线退化成不可见的点。
- 标题区域显示当前值、历史范围和记录点数量。
- 鼠标悬停圆点显示精确记录时间和资源数量。
- 右键圆点只能删除当前资源在当前时间点的记录，不删除同一时间的其他资源记录。

删除图表记录点和清空历史记录都只修改当前编辑数据。清空按钮必须弹出确认窗口；清空后需要点击页面顶部“保存”才能正式生效。

### 空状态与异常状态

- 没有其他物品时，左侧显示“暂无已记录物品”。
- 没有核心资源历史时，右侧显示“暂无识别记录”。
- 自动识别没有可用游戏实例时，提示用户先启动或连接游戏实例。
- 自动识别流程失败时保留已有正式数据，不因一次失败清空页面。
- 某一项 OCR 失败时，不应把该资源写成 0；应保留缺失字段并在日志中记录失败原因。
- 页面重启后只加载正式 `WarehouseData`，不把未完成的草稿当作已保存历史；如需恢复识别草稿，应由页面明确提示用户确认。

### v0.11.1 正式版实现收束

本节记录正式版发布时已经落地的仓库相关约定：

- 仓库自动识别从右上角目录开始，先进入锻刀页面读取核心资源，再进入所持道具页面读取小判和其他物品。
- 所持道具扫描使用分段 OCR：普通页面只读取当前可确认的上方两行，滑动后由原第三行进入可读取位置；最后一页使用专用的下方两行区域，避免到底后提前结束导致遗漏。
- 每次滑动松手后等待 1 秒，再执行 OCR 和到底颜色判断；识别到到底状态后仍完成当前页面的最后一次读取。
- 其他物品按照游戏界面的左到右、上到下顺序保存；名称和数量分别使用可编辑输入框，名称区域优先保证足够宽度。
- 其他物品支持新增、删除、手动改名、数量修改和拖动排序。数量为 0 的条目不显示；保存后的名称会作为后续 OCR 匹配的优先参考。
- 核心资源历史只在用户点击“保存”后写入，图表必须通过“刷新图表”主动刷新；图表按资源分别计算纵轴范围，按实际时间间隔计算横轴位置，并支持悬停查看和右键删除单点。
- 仓库个人数据、识别草稿和资源历史均属于运行时数据，不进入 Git 提交和发布包。
- 自动识别无法识别关键页面时，应安全结束任务并通过界面提示用户，不得继续盲目翻页、卡死或闪退。

正式版范围不包含资源上限提醒和图表导出；这些属于后续可选增强。

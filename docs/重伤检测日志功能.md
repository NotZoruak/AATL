# 重伤检测日志输出功能

## 目标

在各任务流水线检测到刀剑男士重伤时输出日志语句。停止模式下终止当前轮流水线（repeatable 任务会重新拉起的限制见下文）。

## 涉及流水线

- **合战场（Sortie.json）** — 选项 `S_重伤处理`（修刀/停止）
- **地下城（Underground.json）** — 选项 `U_重伤处理`（修刀/停止）

## 实现方案

### 新增自定义动作

`resource/base/custom/DamageLogAction.cs`：从 `custom_action_param` 读取 `message` 字段，调用 `LoggerHelper.Info()` 输出日志，同时调用 `MaaProcessorManager.Instance.Current.AddLog()` 将日志写入 GUI 面板。

### 修刀模式：日志节点插入

保持原有识别和动作逻辑不变，在 `next` 链中插入日志节点。日志后流水线照常进入修复流程。

### 停止模式：日志后终止当前轮

节点链：**识别节点 → 日志节点**（无 next）。日志节点执行后无后续节点，流水线自然终止当前轮。

> 局限性：日志节点无 next 等价于原 DoNothing 行为。对于 repeatable（循环）任务，GUI 任务调度器会在当前轮结束后重新拉起下一轮。彻底终止需 GUI 层支持，从 pipeline 自定义动作中无法可靠实现。

## Sortie.json 改动

| 节点 | 改动 |
|---|---|
| S_IsPreDamage1 | next: `["S_LogPreDamage1"]`（原 `["S_DecideDamage_Pre"]`） |
| S_IsPreDamage2 | next: `["S_LogPreDamage2"]`（原 `["S_ConfirmCancelPreDamage2"]`） |
| S_IsMarchingDamage2 | next: `["S_LogMarchingDamage2"]`（原 `["S_ConfirmCancelMarchingDamage2"]`） |

新增节点：
- `S_LogPreDamage1` → next: `["S_DecideDamage_Pre"]`
- `S_LogPreDamage2` → next: `["S_ConfirmCancelPreDamage2"]`
- `S_LogMarchingDamage2` → next: `["S_ConfirmCancelMarchingDamage2"]`

### 停止模式（`S_重伤处理` = 停止）

| 节点 | 改动 |
|---|---|
| S_StopOnDamagePopup | 去掉 `action`/`on_error`，加 next: `["S_LogStopOnDamage"]` |
| S_StopOnDamageText | 去掉 `action`/`on_error`，加 next: `["S_LogStopOnDamageText"]` |
| S_IsStopOnDamage | 去掉 `action`，加 next: `["S_LogStopOnDamageRepair"]` |

新增节点（均无 next，流水线自然终止）：
- `S_LogStopOnDamage`
- `S_LogStopOnDamageText`
- `S_LogStopOnDamageRepair`

## 不涉及的流水线

远征（Expedition）、江户城（EdoCastle）、刷花（FlowerBrush）、刀解（Disassemble）、回到本丸（GoHome）当前无重伤检测机制，不做修改。

## 已知问题：彻底终止循环任务

尝试过以下方案，均未成功：

1. **MaaFramework 内置 `StopTask` 动作**（v5.11.1 支持）：仅停止引擎级流水线，GUI 调度器仍会拉起下一轮。
2. **自定义动作 `StopTaskAction` 调用 `MaaProcessor.StopTask()`**：编译失败，`MFATaskStatus` 等依赖类型在动态编译上下文中不可解析。
3. **自定义动作 `StopTaskAction` 调用 `MaaTasker.PostStop()`**：编译失败，原因同上（类型依赖链断裂）。

根本原因：pipeline 自定义动作的运行时编译上下文无法解析 GUI 层（MFAAvalonia）的复杂类型依赖。彻底终止需要 GUI 层原生支持，或等待 MaaFramework 提供无需 GUI 上下文即可触发的停止机制。

> 状态：日志输出已验证通过（2026-06-28）。彻底终止循环任务暂不可行。

# 刮刮乐自动识别 — 设计思路

## 问题定义

刀剑乱舞"刮刮乐"：画面显示角色黑色剪影，按 **3×3 九宫格**（300×300，每格 100×100）划分，每次随机露出若干格。**未露出格覆盖彩色涂层，刮除后才露出黑色剪影。** 剪影随机为上半身或下半身。玩家根据露出部分辨认角色。

目标：一键截图 → 自动识别 → 输出角色名。

## 素材

从 `Silhouette1.0.2\silhouette\` 借用 232 张模板（实现前需人工检查修正）：

| 类型 | 数量 | 说明 |
|------|------|------|
| `_head` | 124 | 角色上半身完整九宫格，300×300，黑剪影白底 |
| `_foot` | 107 | 角色下半身完整九宫格，300×300，黑剪影白底 |
| 其他 | 1 | `000170_silhouette_2.png`，角色 00170 的额外变体 |

每张 300×300 即为 3×3 网格母版，等分 9 个 100×100 格子。

除模板图片外不复用 Silhouette 任何代码（NativeAOT 二进制，无可用源码）。算法、截图、UI 全部自研。

## 核心挑战

1. **模板完整，输入残缺** —— 模板是 300×300 九宫格全图，输入只有部分格子露出
2. **head/foot 随机** —— 需同时匹配两种类型，不能预先知道
3. **无网格边框** —— 九宫格没有可见分隔线，只能按固定比例切分
4. **ROI 无法精确对齐** —— 框选的刮刮乐区域必然有像素偏移，直接等分会错位。这是最关键工程难点

## 识别算法

### 核心思路

**露出格在九宫格中的位置是强约束。** 露出的是"第 (1,2) 格"而非"一块随机区域"，位置本身就大幅缩小候选范围。

流程：

```
截图 → 裁出 ROI → 偏移扫描自校准（找到正确对齐）
         ↓
  对齐后 3×3 等分 → 检测露出格
         ↓
  对每个露出格，与全部模板的【同位置格】计算重合度
         ↓
  各格得分取平均 → 得分降序 → 输出结果
```

### 匹配度公式

```
匹配度 = 露出格与模板格同时为"黑"的像素数 / 露出格中"黑"像素数
```

即模板在同位置的剪影覆盖了露出部分的多少。越接近 1.0 越好。公式天然容忍模板略大于露出区域。

### head/foot 统一处理

全部 232 张模板放入同一候选池，不区分类型。匹配得分自然决定结果——如果露出的是上半身，foot 模板得分自然低。

## ROI 自校准对齐

### 问题

框选偏移几个像素 → 固定坐标等分的网格与游戏实际九宫格不重合 → 露出的剪影跨到相邻格 → 同位置比对失效。

### 方案：偏移扫描，得分投票

**框大一圈**（如 320×320 包容 300×300 九宫格），然后扫描偏移量，让匹配得分自己找到正确对齐。

```
对每个偏移 (dx, dy) 在 0~20px 范围：
    取出 300×300 子区域 → 二值化 → 3×3 等分 → 检测露出格
    → 与 232 张模板做同位置格子比对
    → 记录此偏移下的最高匹配得分

取最高得分最大的偏移作为正确对齐，用其匹配结果输出
```

**为什么有效**：错误偏移下露出内容跨格，匹配得分必然低；只有正确偏移下剪影才完整落在对应格内，与正确角色高度重合。对齐信号来自剪影内容本身。

计算量：21×21=441 个偏移 × 232 模板 × 约 2 个露出格 = 约 20 万次 100×100 二值矩阵与运算。现代 CPU 几百毫秒。露出格为 0 的偏移直接跳过，实际更少。

## 架构定位

### 与 AATL 现有系统的关系

复用限锻计算器的 UI 模式（侧边栏入口 + MVVM），但不依赖 MaaFramework 做识别——刮刮乐是纯图像处理，MaaFW 只用来走 ADB 截图。

### 截图 → 像素管线

全部已有设施，不引入新依赖：

```
Screencap()/GetImage()        ADB 从模拟器截屏 → MaaImageBuffer
    ↓
TryGetEncodedData(Stream)     拿到 PNG 编码流
    ↓
SKBitmap.Decode(stream)       SkiaSharp 解码（Avalonia 内置）
    ↓
GetPixels() → IntPtr          逐像素读写
    ↓
裁 ROI + 二值化 + 分格比对
```

### 模板预加载

启动时一次性加载 232 张 PNG → 每张二值化 → 预切 9 个 100×100 格子蒙版 → 常驻内存（约 2.6 MB）。匹配时直接索引 `template[row, col]`。

### 实时预览

识别页面嵌入实时游戏画面（复用 MonitorView 机制）：Image 控件绑定 Bitmap，定时刷新。点"识别"时用当前帧执行匹配，结果显示在画面下方。

## 待标定参数

| 参数 | 说明 |
|------|------|
| ROI 大致坐标 | 1280×720 下刮刮乐区域在画面中的位置，允许 ±10px 误差 |
| 灰度阈值 | 判定像素为"黑"的上限值，影响二值化质量 |
| 露出判定阈值 | 格子内暗像素占比超过多少算"已露出"（建议 5% 起调） |

前两项需要实际截图 A/B 测试标定。

## 边界情况

| 情况 | 处理 |
|------|------|
| 只露出 1 格 | 单格匹配，位置约束足够强 |
| 露出 3+ 格 | 多格取平均，结果更可靠 |
| Top-1/Top-2 得分接近 | 输出前几名供参考，不强行唯一答案 |
| 无暗像素格（尚未刮开） | 提示"尚未露出" |
| 模拟器未连接 | Toast 提示先连接设备 |
| 所有模板得分过低 | 标记为"无法识别" |

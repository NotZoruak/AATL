# 远征任务与长期远征计划设计

## 概述

- 流水线文件：`resource/base/pipeline/Expedition.json`
- 入口节点：`Expedition`（同时也是主枢纽）
- 节点前缀：`E_`
- 总节点数：158（有识别 82、纯路由 17、含 on_error 69）

## GUI 选项

| 选项 | 类型 | 说明 |
|------|------|------|
| 部队一 ～ 五 远征地图 | select | 休息 / 1-1 ～ 5-4 |
| 刷新间隔（秒） | input（int） | 默认 600 秒 |
| 远征智能调度 | switch（全局） | 按最短间隔检查并补派 |
| 长期远征计划 | switch（全局） | 派遣前检查疲劳值，低于阈值自动刷花 |

## 主枢纽 `Expedition`

16 个检测节点，超时 120s，超时后 `on_error → E_RestartGame` 重启游戏。首位 `E_IsTroopRecordPage` 防止误触部队记录页面后卡死。

```json
"Expedition": {
    "pre_delay": 0,
    "timeout": 120000,
    "on_error": ["E_RestartGame"],
    "next": [
        "E_IsTroopRecordPage",
        "E_IsAnnouncementPopup", "E_IsLoginReward",
        "E_ClickExpeditionReturn_Exp", "E_ClickExpeditionReturn_Title",
        "E_DetectExpeditionScreen", "E_IsMenuDirectory", "E_IsTeamStatusPanel",
        "E_CheckHomeBrightness",
        "E_IsGameIcon", "E_IsLoginButton",
        "E_IsGameUpdatePopup", "E_IsInGameUpdatePopup",
        "E_IsInternalReport", "E_IsSwordDropColor",
        "E_FallbackWait"
    ]
}
```

`E_IsTroopRecordPage` TemplateMatch `部队记录页面.png`（ROI `[577,8,130,35]`，阈值 0.95），命中后点击 `[63,28,17,17]` 返回。

## 主流程链路

```
Expedition（枢纽）
   ├── E_IsTroopRecordPage → 点击返回重入枢纽
   ├── 远征归来弹窗处理（点击关闭）
   ├── 已在远征画面检测 → E_GoHome → 返回本丸
   ├── 菜单目录检测 → E_ClickBackToHome → E_WaitRefresh
   ├── 队伍状态面板检测 → E_ExpSubHub1（跳过本丸检测）
   ├── 本丸检测 → E_CheckTeamStatus → 部队级联检测
   ├── 闪退恢复 / 弹窗关闭
   └── E_FallbackWait → 回枢纽
```

## 部队检测链路

```
E_CheckTeamN（OCR ["机","队员"] 判断待机）
  → E_SelectTeamN（TemplateMatch 本丸远征.png 确认面板）
    → E_VerifyScreenN（OCR "远征目的地选择" 双重验证）
      ├─ 命中 → E_SelectMapN → E_ClickSmallMapN → E_ConfirmDispatchN
      └─ 未命中 → E_DetectHome
        → E_SelectTeamBtnN（OCR "部队选择"→点击部队按钮）
          → E_MarkTeamN（DispatchLogAction mark）
            → E_StartExpedition → E_VerifyConfirmPopup（OCR "远征确认"）
              ├─ 命中 → E_ConfirmExpedition → E_LogDispatch → E_GoHome
              └─ 未命中 → E_VerifyTeamSelect → 重试出阵
```

长期远征计划开启时，`pipeline_override` 将 `E_MarkTeamN.next` 改为 `["E_UseTeamRecordN"]`，插入部队记录恢复与疲劳检测。

### 部队 N 参数差异

| 参数 | 部队一 | 部队二 | 部队三 | 部队四 | 部队五 |
|------|--------|--------|--------|--------|--------|
| CheckTeam ROI Y | 38 | 152 | 268 | 383 | 498 |
| CheckTeam enabled | false | true | true | true | true |
| SelectTeamBtn target X | 157 | 276 | 405 | 522 | 638 |

> `E_CheckTeam1` 默认 `enabled: false`（部队一默认休息），选择地图后由 pipeline_override 启用。

### 部队间级联

```json
"E_ExpSubHub1": { "next": ["E_CheckTeam1", "E_ExpSubHub2"] },
"E_ExpSubHub2": { "next": ["E_CheckTeam2", "E_ExpSubHub3"] },
"E_ExpSubHub3": { "next": ["E_CheckTeam3", "E_ExpSubHub4"] },
"E_ExpSubHub4": { "next": ["E_CheckTeam4", "E_ExpSubHub5"] },
"E_ExpSubHub5": { "next": ["E_CheckTeam5", "E_AllTeamsBusy"] }
```

某部队休息时 SubHub 顺延到下一个 SubHub。

### 部队记录链路（长期远征计划）

`E_MarkTeamN → E_UseTeamRecordN → E_UseTeamRecord_Step1_RecN → E_UseTeamRecord_Step2_RecN → E_CheckFatigueN`

- Step1 TemplateMatch `部队记录.png`（ROI `[1139,132,124,41]`，阈值 0.95）
- Step2 TemplateMatch `使用记录.png`（ROI `[707,53,72,64]`，阈值 0.98），点击对应记录坐标

各记录点击 Y：140 / 250 / 360 / 465 / 575。所有 Rec 节点均已配置 `on_error: ["Expedition"]`。

### 全部忙线处理

```json
"E_AllTeamsBusy": {
    "action": { "type": "Click", "param": { "target": [230, 12, 71, 19] } },
    "next": ["E_GoHome"],
    "pre_delay": 100
}
```

全部在远征中或均休息时，点击左上角返回本丸。

## 返回本丸链路

```
E_GoHome（路由）
  → E_ClickDirectoryTop（OCR "目" ROI [1183,18,87,40]）→ 点击
    → E_PostClickDirectoryHub（路由）
      ├─ E_VerifyMenuDir（TemplateMatch 菜单目录.png ROI [581,28,112,57]）
      │   → E_ClickBackToHome（点击 [1037,169,110,44]）→ E_WaitRefresh
      ├─ E_CheckNavDirRetry_Exp（OCR "目" 兜底重试）
      └─ Expedition（回到枢纽）
```

`E_ClickDirectoryTop` 使用 OCR 识别"目"字（精简后的目录标签），pre_delay 3000 确保菜单动画完成。

## 刷新等待

```json
"E_WaitRefresh": {
    "action": "DoNothing",
    "post_delay": 60000,
    "next": ["Expedition"]
}
```

`post_delay` 由 `RefreshInterval` 选项通过 `"{seconds}000"` 覆盖。默认 600 秒 = 600000ms（10 分钟）。

## 重启游戏

```json
"E_RestartGame": {
    "action": { "type": "Custom", "custom_action": "RestartGameAction" },
    "next": ["Expedition"]
}
```

`RestartGameAction` 读取运行时 ADB 配置，杀模拟器进程后重拉并等待 ADB 重连（最长 60s），再 `monkey` 启动游戏。包名从 GUI「目标应用」读取，默认 `com.youzu.djlw`。

## 自定义动作

| 动作 | 节点 | 说明 |
|------|------|------|
| `DispatchLogAction` | `E_MarkTeam1~5`（mark）/ `E_LogDispatch`（log） | 远征派遣记录与日志输出 |
| `RestartGameAction` | `E_RestartGame` / `E_FlowerRestartGame` | 杀模拟器 + 重启游戏 |
| `FatigueCheckAction` | `E_CheckFatigue1~5`（check_all）/ `E_FlowerCheckCaptain`（check_captain） | 疲劳值检测 |
| `SelectFlowerTeamAction` | `E_FlowerTeamSelect` | 刷花部队选择 |
| `ExpeditionTimerAction` | `E_TimerStart` | 开启：OCR 扫描 + 启计时 + 关面板；关闭：仅关面板 |
| `ExpeditionTimerCheckAction` | `E_CheckTimerExpired` | 检查计时器，true=未过期→next，false=已过期→on_error。关闭时静默 |
| `ExpeditionTimeTracker` | `E_TrackerOCR` | OCR 扫描归队时间，存入 ExpeditionReturnTracker，供 SmartWaitAction 使用 |
| `SmartWaitAction` | `E_SmartWait` | 读取最早归队时间，动态等待 min(最早, 间隔) |
| `ExpeditionMapSelectAction` | 同步远征覆盖 `E_SelectMapN` | 直接选择远征地图 |

## 后台计时器

`E_TimerStart` 执行 `ExpeditionTimerAction.Run()`，行为随「远征智能调度」开关变化：

**开启时**：OCR 扫描五个部队剩余时间（`ExpeditionTimeTracker.ScanAndStore`）→ 取 min(最早归队, 配置间隔) → 关面板 → `ExpeditionTimerRecognition.StartTimer` 启计时 → 日志"倒计时开始"。`E_CheckTimerExpired` 检查：未归零（true）→ next 继续出阵；已归零（false）→ on_error → Expedition 检查。首次启动（timer 为 null）视为已过期。

**关闭时**：仅关闭面板，不启计时器、不打日志。`E_CheckTimerExpired` 因计时器从未启动，`IsExpired()` 始终返回 true → 每次回本丸都走 on_error 进 Expedition 检查。

合战场同步远征依赖此机制：关闭时每次 S_IsHome 自然进 Expedition，开启时按计时器频率。陆联同步远征中 `LR_IsTeamSelect → E_CheckTimerExpired` 由智能调度开启 case 注入，关闭时不注入，陆联选队时永不触发回本丸。

### 智能等待（独立远征 / 合战场）

`E_TrackerOCR`（`ExpeditionTimeTracker`）用于独立远征任务，OCR 扫描归队时间后 `E_SmartWait`（`SmartWaitAction`）取 min(最早归队, 间隔) 动态等待。合战场同步远征走 `E_TimerStart → ExpeditionTimerAction` 内部扫描路径，逻辑共用。

## on_error 覆盖策略

- 主枢纽 next 列表中所有节点不设 on_error，失败后枢纽继续扫描下一个
- 主枢纽自身 `on_error → E_RestartGame`
- 子枢纽 `E_FlowerBattleHub` 同理
- 部队链路中有识别的节点 on_error 指向 `Expedition`（纯 click/Custom 节点无需）；刷花链路中有识别的节点指向 `E_FlowerBattleHub`
- `E_DetectHome` 自循环直到确认在本丸
- `E_PostClickDirectoryHub` on_error 指向 `Expedition`

## 长期远征计划

### 概述

全局 switch，默认关闭。派遣前 OCR 队伍六个位置的疲劳值，低于阈值自动 1-1 单次刷花，直到全队达标。

### 主流程

```
E_MarkTeamN → E_UseTeamRecordN（恢复部队记录预设编队）
  → E_CheckFatigueN（OCR 六位疲劳值）
    ├─ 全部 ≥ 阈值 → E_StartExpedition → ... → 正常派遣
    └─ 有 < 阈值 → E_FlowerNavigate → E_FlowerBattleHub（刷花）
        → E_FlowerDone → E_GoHome → 继续远征派遣
```

### 刷花子枢纽 `E_FlowerBattleHub`

19 个检测节点，超时 120s，`on_error → E_FlowerRestartGame`。模拟 1-1 出阵全部场景：目录菜单 → 出阵 → 维新时代 → 1-1 地域 → 部队选择 → 解散换队长 → 出阵 → 行军/阵形/战斗结果流转 → 回到枢纽。

### 解散与换队长

`E_FlowerDissolve` 路由节点，`next: ["E_FlowerDissolveCheck", "E_FlowerCaptainClickSlot"]`。

`E_FlowerDissolveCheck` ColorMatch 灰度检测（ROI `[1075,211,36,420]`，upper `[46,46,46]`，lower `[40,40,40]`，method 4），检测到未使用槽位即点击叉掉，自循环直到 2-6 号位清空。完成后走 `E_FlowerCaptainClickSlot` 点击队长槽位进入换队长。

### 疲劳检测与终止

```json
"E_FlowerCheckCaptain": {
    "action": { "type": "Custom", "custom_action": "FatigueCheckAction",
                "custom_action_param": { "mode": "check_captain" } },
    "next": ["E_FlowerDone"],
    "on_error": ["E_FlowerSortie"],
    "pre_delay": 100
}
```

- 新队长值 ≥ 阈值 → `E_FlowerDone → E_GoHome`（完成刷花，跳出）
- 新队长值 < 阈值 → `E_FlowerSortie`（即刻出阵 1-1 继续）

### 导航入口

`E_FlowerNavigate` OCR "目"（ROI `[1183,18,87,40]`）点击目录，进入 `E_FlowerBattleHub`。

## 同步远征集成

其他任务通过同步远征选项复用远征流水线。`E_SelectMapN` 被覆盖为 `ExpeditionMapSelectAction`，`E_ClickSmallMapN` 被禁用。

| 覆盖节点 | 覆盖值 | 说明 |
|----------|--------|------|
| `S_IsHome.next` | `E_CheckTimerExpired` | 合战场回本丸走计时检查 |
| `{前缀}IsHome.next` | `["Expedition"]` | 陆联回本丸自然跳远征 |
| `E_SelectMapN.action` | `ExpeditionMapSelectAction` | 直接选图 |
| `E_ClickSmallMapN.enabled` | `false` | 禁用小地图点击 |
| `E_AllTeamsBusy.next` | `E_TimerStart` | 忙线回原任务 |
| `E_ClickBackToHome.next` | 原任务等待节点 | 远征结束回原任务 |

智能调度开启时额外注入 `LR_IsTeamSelect → E_CheckTimerExpired`，为陆联选队页注入计时链路。关闭时不注入，陆联选队时永不主动回本丸。

## 部队地图坐标映射

interface.json 的部队一~五选项中，每个地图 case 通过 pipeline_override 设置 `E_SelectMapN.target` 和 `E_ClickSmallMapN.target`。共 20 个地图（1-1 ~ 5-4），SelectMap 按时代 5 组、ClickSmallMap 按地域 4 组。

## 设计要点

- **部队记录页面防御**：`E_IsTroopRecordPage` 首位检测，命中后点击返回避免卡死
- **串行检测**：SubHub 级联依次派遣，非并行
- **休息跳过**：`E_CheckTeam1` 默认 disabled，其余默认 enabled
- **双重验证**：`E_VerifyScreenN` OCR 确保在远征画面，未命中回退 `E_DetectHome`
- **目录重试**：`E_PostClickDirectoryHub` 三路分流（验证目录 → 点击回本丸 / OCR 重试 / 回枢纽兜底）
- **面板复用**：`E_IsTeamStatusPanel` 跳过本丸检测直接进入部队选择
- **超时重启**：主/子枢纽超时自动重启游戏
- **疲劳阈值**：默认 91，可自定义
- **刷花终止**：OCR 首位队长疲劳值，≥ 阈值跳出，避免无限循环

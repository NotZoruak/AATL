# 远征任务设计

## 概述

- 流水线文件：`resource/base/pipeline/Expedition.json`
- 入口节点：`Expedition`（同时也是主枢纽）
- 节点前缀：`E_`
- 总节点数：约 70

## GUI 选项

| 选项 | 类型 | 说明 |
|------|------|------|
| 部队一 远征地图 | select | 休息 / 1-1 ～ 5-4，选择后自动设置对应的地图坐标 |
| 部队二 远征地图 | select | 同上 |
| 部队三 远征地图 | select | 同上 |
| 部队四 远征地图 | select | 同上 |
| 部队五 远征地图 | select | 同上 |
| 刷新间隔（秒） | input（int） | 默认 600 秒（10 分钟），通过 pipeline_override 设置 `E_WaitRefresh.post_delay` |

```json
{
    "name": "远征",
    "entry": "Expedition",
    "default_check": true,
    "repeatable": false,
    "repeat_count": 0,
    "option": [
        "部队一",
        "部队二",
        "部队三",
        "部队四",
        "部队五",
        "RefreshInterval"
    ],
    "label": "远征",
    "description": "请确保编队符合远征要求。远征队伍中不能有成员处于中伤或重伤状态"
}
```

## 主枢纽 `Expedition`

入口节点即主枢纽，14 个检测节点，全局超时 120 秒，超时后触发重启游戏：

```json
"Expedition": {
    "pre_delay": 0,
    "next": [
        "E_IsAnnouncementPopup",
        "E_IsLoginReward",
        "E_ClickExpeditionReturn_Exp",
        "E_ClickExpeditionReturn_Title",
        "E_DetectExpeditionScreen",
        "E_IsMenuDirectory",
        "E_IsTeamStatusPanel",
        "E_CheckHomeBrightness",
        "E_IsGameIcon",
        "E_IsLoginButton",
        "E_IsGameUpdatePopup",
        "E_IsInGameUpdatePopup",
        "E_IsInternalReport",
        "E_FallbackWait"
    ],
    "timeout": 120000,
    "on_error": ["E_RestartGame"]
}
```

## 主流程链路

```
Expedition（枢纽）
   │
   ├── 远征归来弹窗处理 ───────────────────────────────────────┐
   │     E_ClickExpeditionReturn_Exp / E_ClickExpeditionReturn_Title
   │     点击关闭后回到 Expedition
   │
   ├── 已在远征画面检测 ──────────────────────────────────────┐
   │     E_DetectExpeditionScreen → E_GoHome → 返回本丸链路
   │
   ├── 菜单目录检测 ──────────────────────────────────────────┐
   │     E_IsMenuDirectory → E_ClickBackToHome → E_WaitRefresh
   │
   ├── 已在队伍状态面板检测 ─────────────────────────────────┐
   │     E_IsTeamStatusPanel → E_ExpSubHub1（跳过本丸检测）
   │
   ├── 本丸检测 ──────────────────────────────────────────────┐
   │     E_CheckHomeBrightness → E_DetectHome → E_CheckTeamStatus
   │       │                                                   │
   │       └── E_ExpSubHub1 → E_CheckTeam1 ──→ 远征 1 ──→ E_ExpSubHub2
   │                            │ (休息则跳过)      │           │
   │                            └── E_ExpSubHub2 → E_CheckTeam2 ──→ ...
   │                                                                 │
   │       E_ExpSubHub5 → E_CheckTeam5 ──→ 远征 5 ──→ E_AllTeamsBusy
   │                       │ (休息则跳过)      │
   │                       └── E_AllTeamsBusy → E_GoHome
   │
   ├── 闪退恢复 / 弹窗关闭（下方详述）
   │
   └── E_FallbackWait → DoNothing → 回到 Expedition
```

## 部队检测链路（部队 N 通用流程）

以部队一为例，部队二~五结构完全一致（仅坐标和 OCR ROI 不同）：

```
E_CheckTeamN（OCR ["机","队员"] 判断是否待机）
    ↓ 命中
E_SelectTeamN（TemplateMatch "本丸远征.png" 确认队伍面板）→ E_VerifyScreenN
    ↓ 命中
E_VerifyScreenN（OCR "远征目的地选择" 双重验证）
    ├── 命中 → E_SelectMapN
    └── 未命中 → E_DetectHome（面板已关，回本丸检测）
    ↓ 命中
E_SelectMapN（点击时代/地图选项，默认值会被 interface 选项覆盖）
    ↓
E_ClickSmallMapN（点击小地图目标位置，默认值会被 interface 选项覆盖）
    ↓
E_ConfirmDispatchN（点击决定按钮）
    ↓
E_SelectTeamBtnN（OCR "部队选择" 确认→点击对应部队按钮）
    ↓
E_MarkTeamN（DispatchLogAction mode:"mark" 记录派遣）
    ↓
E_StartExpedition（点击出阵按钮，post_delay: 800）
    ↓
E_VerifyConfirmPopup（OCR "远征确认"）
    ├── 命中 → E_ConfirmExpedition → E_LogDispatch → E_GoHome
    └── 未命中 → E_VerifyTeamSelect（补选部队 → 重新 E_StartExpedition）
```

### 部队间级联

`E_ExpSubHub1~5` 串联五个部队的检测链路：

```json
"E_ExpSubHub1": { "next": ["E_CheckTeam1", "E_ExpSubHub2"] },
"E_ExpSubHub2": { "next": ["E_CheckTeam2", "E_ExpSubHub3"] },
"E_ExpSubHub3": { "next": ["E_CheckTeam3", "E_ExpSubHub4"] },
"E_ExpSubHub4": { "next": ["E_CheckTeam4", "E_ExpSubHub5"] },
"E_ExpSubHub5": { "next": ["E_CheckTeam5", "E_AllTeamsBusy"] }
```

当某部队为"休息"（`E_CheckTeamN` 未启用）时，SubHub 的 next 顺延到下一个 SubHub，自然跳过该部队。

## 本丸检测

```json
"E_CheckHomeBrightness": {
    "recognition": "ColorMatch",
    "roi": [66, 58, 11, 13],
    "upper": [40, 155, 30],
    "lower": [23, 95, 15],
    "action": "DoNothing",
    "next": ["E_DetectHome"]
}
```

```json
"E_DetectHome": {
    "recognition": {
        "type": "TemplateMatch",
        "param": {
            "roi": [8, 1, 71, 107],
            "template": "本丸.png",
            "green_mask": true,
            "threshold": [0.98]
        }
    },
    "next": ["E_CheckTeamStatus", "E_DetectHome"],
    "on_error": ["Expedition"]
}
```

`E_DetectHome` 自循环检测直到确认在本丸，然后进入队伍状态检测。

```json
"E_CheckTeamStatus": {
    "recognition": {
        "type": "OCR",
        "param": {
            "roi": [5, 365, 40, 71],
            "expected": "状"
        }
    },
    "action": {
        "type": "Click",
        "param": { "target_offset": [7, 3, 0, 0] }
    },
    "next": ["E_IsTeamStatusPanel", "Expedition"],
    "post_delay": 1000,
    "pre_delay": 100
}
```

OCR 识别队伍状态面板标签"状"字并点击，然后经过 `E_IsTeamStatusPanel` 验证面板确实已打开（TemplateMatch `本丸远征.png`）再进入部队选择。验证失败则回 `Expedition` 枢纽。

## 刷新等待

```json
"E_WaitRefresh": {
    "action": "DoNothing",
    "post_delay": 60000,
    "next": ["Expedition"]
}
```

`E_WaitRefresh` 等待指定时间后重新进入 Expedition 枢纽。JSON 中基础默认值为 60000ms（1 分钟），实际运行时由 `RefreshInterval` 选项的 pipeline_override 覆盖：

```json
"RefreshInterval": {
    "name": "RefreshInterval",
    "label": "刷新间隔（秒）",
    "type": "input",
    "inputs": [{
        "name": "seconds",
        "label": "间隔（秒）",
        "default": "600",
        "pipeline_type": "int",
        "description": "默认 600 秒 = 10 分钟"
    }],
    "pipeline_override": {
        "E_WaitRefresh": {
            "post_delay": "{seconds}000"
        }
    }
}
```

用户默认输入 600 秒，拼接 `000` 后得到 600000ms（10 分钟）。

## 闪退恢复节点

| 节点 | 类型 | 行为 |
|------|------|------|
| `E_IsAnnouncementPopup` | TemplateMatch `公告弹窗.png` | 自循环点击关闭，`timeout: 3000` |
| `E_IsLoginReward` | TemplateMatch `登录奖励.png` | 点击第一下 → `E_LoginRewardClick2` |
| `E_LoginRewardClick2` | Click `[1092, 318]` | 点击第二下，`pre_delay: 1000` |
| `E_LoginRewardClick3` | Click `[1092, 318]` | 点击第三下后回环检测，`timeout: 3000`, `pre_delay: 1000` |
| `E_IsInternalReport` | TemplateMatch `内番报告.png` | 点击关闭 |
| `E_IsGameIcon` | TemplateMatch 全屏 `游戏图标.png` | 点击重进游戏，`post_delay: 3000` |
| `E_IsLoginButton` | TemplateMatch `登录.png` | 点击登录，`post_delay: 3000` |
| `E_IsGameUpdatePopup` | TemplateMatch `游戏更新.png` | 关闭商店更新弹窗，`post_delay: 2000` |
| `E_IsInGameUpdatePopup` | OCR "更新" | 点击关闭游戏内更新弹窗，`post_delay: 2000` |
| `E_FallbackWait` | DoNothing | 兜底等待，回 Expedition 枢纽 |

### 重新登录链路

```
E_IsAnnouncementPopup（关公告）→ 自循环直到无公告
E_IsLoginReward → E_LoginRewardClick2 → E_LoginRewardClick3 → 回环检测
E_IsInternalReport（关内番报告）
E_IsGameIcon（点击图标重进）→ E_IsLoginButton（点击登录）
```

## 重启游戏

```json
"E_RestartGame": {
    "action": {
        "type": "Custom",
        "custom_action": "RestartGameAction"
    },
    "next": ["Expedition"]
}
```

当 Expedition 枢纽超时（120 秒内所有 next 均未命中），触发 `E_RestartGame` 调用 `RestartGameAction` 自定义动作重启游戏，之后回到 Expedition 枢纽重新开始。

## 部队地图坐标映射

interface.json 的 `部队一`~`部队五` 选项中，每个 `cases` 分支通过 pipeline_override 设置对应地图的 `E_SelectMapN` 和 `E_ClickSmallMapN` 的 target 坐标，覆盖 Expedition.json 中的默认值。

以部队一 `1-1` 为例：

```json
{
    "name": "1-1",
    "pipeline_override": {
        "E_CheckTeam1": { "enabled": true },
        "E_SelectMap1": { "target": [276, 188, 37, 39] },
        "E_ClickSmallMap1": { "target": [173, 365, 97, 96] }
    }
}
```

`休息` 分支仅设置 `E_CheckTeam1.enabled: false`，使该部队在 SubHub 中自然跳过。

### 部队二~五的休息分支

部队二~五的"休息"分支分别设置对应 `E_CheckTeam2~5.enabled: false`。非休息分支仅设置 `E_SelectMapN.target` 和 `E_ClickSmallMapN.target`，不重复设置 `enabled`（因为 E_CheckTeam2~5 默认 `enabled: true`）。

### 可选地图范围

每个部队支持 20 个地图：1-1 ～ 1-4、2-1 ～ 2-4、3-1 ～ 3-4、4-1 ～ 4-4、5-1 ～ 5-4。

SelectMap 的 target 按时代分为 5 组（维新的记忆=1、江户的记忆=2、幕末的记忆=4、延享的记忆=3、享保的记忆=5），ClickSmallMap 的 target 按地域分为 4 组。

## 自定义动作

### DispatchLogAction

位于 `E_MarkTeam1~5` 和 `E_LogDispatch` 节点中。

- `mode: "mark"`（E_MarkTeam1~5）：记录部队已派遣标记，参数 `team: 1~5` 标识部队编号
- `mode: "log"`（E_LogDispatch）：输出派遣汇总日志到 GUI 面板

### ExpeditionMapSelectAction

自定义动作，负责根据部队选项选择对应的远征地图坐标。在独立远征流程中不直接使用；在"同步远征"模式下（合战场/地下城的 `S_同步远征` / `U_同步远征` 选项），`E_SelectMapN` 被覆盖为该动作，跳过"点击时代→点击小地图"的两步流程，直接选择目标地图，同时禁用 `E_ClickSmallMapN`。

### RestartGameAction

`E_RestartGame` 节点调用，用于在流水线卡死时重启游戏进程。

## 设计要点

- **串行检测**：五个部队按顺序逐一检测，使用 SubHub 级联而非并行，确保依次派遣
- **休息跳过**：`E_CheckTeam1` 默认 `enabled: false`（部队一默认休息），`E_CheckTeam2~5` 默认 `enabled: true`。选择地图后 pipeline_override 启用对应部队
- **双重验证**：`E_VerifyScreenN` OCR "远征目的地选择" 确保确实在远征画面，避免误操作；未命中时回退到 `E_DetectHome`
- **自循环 home 检测**：`E_DetectHome` 自循环等待本丸加载，`on_error` 回到 Expedition 重新走枢纽
- **忙线处理**：`E_AllTeamsBusy` 在所有部队均不可派遣时（全部在远征中/全部休息）返回本丸
- **动态间隔**：`E_WaitRefresh.post_delay` 由 `RefreshInterval` 选项通过 pipeline_override 动态设置，JSON 基础默认 60000ms，用户界面默认 600 秒拼接后为 600000ms
- **超时重启**：Expedition 枢纽 `timeout: 120000`，超时后通过 `E_RestartGame` 重启游戏
- **目录重试机制**：`E_CheckNavDirRetry_Exp` 作为点击目录按钮后的兜底重试，避免因 OCR 识别波动导致流程中断
- **面板复用检测**：`E_IsTeamStatusPanel` 检测已在队伍状态面板的情况（如从其他流水线同步远征跳入），跳过本丸检测直接进入部队选择

## 同步远征集成

### 工作机制

其他任务（合战场、地下城、陆联）通过"同步远征"选项可以复用远征流水线。启用后，任务回本丸时跳转到 `Expedition` 枢纽，检测并派遣空闲队伍，完成后返回原任务继续执行。

同步远征使用 `ExpeditionMapSelectAction` 自定义动作选择地图（而非 pipeline 中的两步点击），同时 `E_ClickSmallMapN` 被禁用。

### pipeline_override 要点

每个同步远征选项需要覆盖以下节点：

| 节点 | 覆盖 | 说明 |
|------|------|------|
| `{前缀}IsHome.next` | `["Expedition"]` | 回本丸时跳转远征流水线 |
| `E_CheckTeam1.enabled` | `true` | 强制启用部队一（远征任务默认禁用） |
| `E_SelectMapN.action` | `ExpeditionMapSelectAction` | 使用自定义动作选图 |
| `E_ClickSmallMapN.enabled` | `false` | 禁用小地图点击 |
| `E_VerifyScreenN.on_error` | `["E_CheckTeamStatus"]` | 验证失败回队伍面板 |
| `E_ClickBackToHome` | next 指向 `{前缀}WaitRefresh` | 远征结束回原任务等待节点 |
| `E_AllTeamsBusy.next` | `["{前缀}NavigateTo..."]` | 全部忙线回原任务活动页 |
| `{前缀}WaitRefresh.enabled` | `true` | 启用等待节点 |

### 新增同步远征任务的代码修改

同步远征复用远征任务的部队一~五配置（休息/地图选择）是通过 `MaaProcessor.CreateNodeAndParam` 中硬编码的任务入口名判断实现的。新增同步远征任务时，除 `interface.json` 和流水线 JSON 外，还需修改：

```csharp
// 5. 合战场/地下城/陆联同步远征：自动复用远征任务的队伍配置
if (task.InterfaceItem?.Entry == "Sortie" || task.InterfaceItem?.Entry == "Underground" || task.InterfaceItem?.Entry == "LRentaisen")
```

否则新任务的 pipeline_override 不会包含远征任务的部队配置，导致 `E_CheckTeam1.enabled: true` 无法被用户的"休息"设置覆盖。

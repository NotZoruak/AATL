# 远征任务设计

## 概述

- 流水线文件：`resource/base/pipeline/Expedition.json`
- 入口节点：`Expedition`（同时也是主枢纽）
- 节点前缀：`E_`
- 总节点数：约 80

## GUI 选项

| 选项 | 类型 | 说明 |
|------|------|------|
| 部队一 远征地图 | select | 休息 / 1-1 ～ 5-4，选择后自动设置对应的地图坐标 |
| 部队二 远征地图 | select | 同上 |
| 部队三 远征地图 | select | 同上 |
| 部队四 远征地图 | select | 同上 |
| 部队五 远征地图 | select | 同上 |
| 刷新间隔（秒） | input（int） | 默认 600 秒（10 分钟），通过 pipeline_override 设置 E_WaitRefresh.post_delay |

## 主枢纽 `Expedition`

入口节点即主枢纽，14 个检测节点：

```json
"Expedition": {

    "next": [
```

## 主流程链路

```
Expedition（枢纽）
   │
   ├── 远征归来弹窗处理 ───────────────────────────────────────┐
   │     E_ClickExpeditionReturn_Exp / E_ClickExpeditionReturn_Title
   │     点击关闭后回到 Expedition
   │
   ├── 已在远征画面检测 ──────────────────────────────────────┐
   │     E_DetectExpeditionScreen → E_GoHome → 回本丸等待
   │
   ├── 菜单目录检测 ──────────────────────────────────────────┐
   │     E_IsMenuDirectory → E_ClickBackToHome → E_WaitRefresh
   │
   ├── 本丸检测 ──────────────────────────────────────────────┐
   │     E_CheckHomeBrightness → E_DetectHome → E_CheckTeamStatus
   │       │                                                   │
   │       └── E_ExpSubHub1 → E_CheckTeam1 ──→ 远征 1 ──→ E_ExpSubHub2
   │                            │ (休息则跳过)      │           │
   │                            └── E_ExpSubHub2 → E_CheckTeam2 ──→ ...
   │                                                                 │
   │       E_ExpSubHub5 → E_CheckTeam5 ──→ 远征 5 ──→ E_AllTeamsBusy
   │                       │ (休息则跳过)      │
   │                       └── E_AllTeamsBusy → E_GoHome
   │
   ├── 闪退恢复 / 弹窗关闭（下方详述）
   │
   └── E_FallbackWait → DoNothing → 回到 Expedition
```

## 部队检测链路（部队 N 通用流程）

以部队一为例，部队二~五结构完全一致（仅坐标和 OCR ROI 不同）：

```
E_CheckTeamN（OCR "机" 判断是否待机）
    ↓ 命中
E_SelectTeamN（TemplateMatch "本丸远征.png" 确认队伍面板）→ E_VerifyScreenN
    ↓ 命中
E_VerifyScreenN（OCR "远征目的地选择" 双重验证）
    ├── 命中 → E_SelectMapN
    └── 未命中 → E_DetectHome（面板已关，回本丸检测）
    ↓ 命中
E_SelectMapN（点击时代/地图选项）
    ↓
E_ClickSmallMapN（点击小地图目标位置）
    ↓
E_ConfirmDispatchN（点击决定按钮，target [1199, 636]）
    ↓
E_SelectTeamBtnN（OCR "部队选择" 确认→点击对应部队按钮 → E_MarkTeamN）
    ↓
E_StartExpedition（点击出阵按钮，post_delay: 800）
    ↓
E_VerifyConfirmPopup（OCR "远征确认"）
    ├── 命中 → E_ConfirmExpedition → E_LogDispatch → E_GoHome
    └── 未命中 → E_VerifyTeamSelect（补选部队 → 重新 E_StartExpedition）
```

### 部队一节点

```json
"E_CheckTeam1": {
    "recognition": {
        "type": "OCR",
        "param": {
            "roi": [162, 37, 81, 32],
            "expected": "机"
        }
    },
    "next": ["E_SelectTeam1"],
    "enabled": false
}
```

> E_CheckTeam1 默认 `enabled: false`（部队一默认休息），由 interface.json 的 pipeline_override 通过 `E_CheckTeam1.enabled: true` 启用。部队二~五默认 `enabled: true`。

```json
"E_VerifyScreen1": {
    "recognition": {
        "type": "OCR",
        "param": {
            "roi": [516, 57, 250, 47],
            "expected": "远征目的地选择"
        }
    },
    "next": ["E_SelectMap1", "E_DetectHome"],
    "on_error": ["Expedition"]
}
```

### 部队间级联

`E_ExpSubHub1~5` 串联五个部队的检测链路：

```json
"E_ExpSubHub1": { "next": ["E_CheckTeam1", "E_ExpSubHub2"] },
"E_ExpSubHub2": { "next": ["E_CheckTeam2", "E_ExpSubHub3"] },
"E_ExpSubHub3": { "next": ["E_CheckTeam3", "E_ExpSubHub4"] },
"E_ExpSubHub4": { "next": ["E_CheckTeam4", "E_ExpSubHub5"] },
"E_ExpSubHub5": { "next": ["E_CheckTeam5", "E_AllTeamsBusy"] }
```

当某部队为"休息"（`E_CheckTeamN` 未启用）时，SubHub 的 next 顺延到下一个 SubHub，自然跳过该部队。

### 全部忙线处理

```json
    "recognition": {
```

## 刷新等待

```json
"E_WaitRefresh": {
    "action": "DoNothing",
    "post_delay": 60000,
    "next": ["Expedition"]
}
```

`E_WaitRefresh` 等待指定时间后重新进入 Expedition 枢纽。`post_delay` 由 `RefreshInterval` 选项的 `pipeline_override` 动态设置（格式：`{seconds}000`，将秒数拼为毫秒值），默认 600000ms（10 分钟）。

## 闪退恢复节点

| 节点 | 类型 | 行为 |
|------|------|------|
| `E_IsAnnouncementPopup` | TemplateMatch `公告弹窗.png` | 自循环关闭，`timeout: 3000` |
| `E_IsLoginReward` + `E_LoginRewardClick2` + `E_LoginRewardClick3` | TemplateMatch + Click×2 | 三击关闭，`timeout: 3000` |
| `E_IsInternalReport` | TemplateMatch `内番报告.png` | 点击关闭 |
| `E_IsGameIcon` | TemplateMatch 全屏 | 点击重进，`post_delay: 3000` |
| `E_IsLoginButton` | TemplateMatch `登录.png` | 点击登录，`post_delay: 3000` |
| `E_IsGameUpdatePopup` | TemplateMatch `游戏更新.png` | 关闭商店更新弹窗，`post_delay: 2000` |
| `E_IsInGameUpdatePopup` | OCR "更新" | 关闭游戏内更新弹窗，`post_delay: 2000` |
| `E_FallbackWait` | DoNothing | 回 Expedition 枢纽 |

## 部队地图坐标映射

interface.json 的 `部队一`~`部队五` 选项中，每个 `cases` 分支通过 pipeline_override 设置对应地图的 `E_SelectMapN` 和 `E_ClickSmallMapN` target 坐标。SelectMap 选择时代、ClickSmallMap 点击小图进入具体地图。

以部队一 `1-1` 为例：

```json
{
    "name": "1-1",
    "pipeline_override": {
        "E_CheckTeam1": { "enabled": true },
        "E_SelectMap1": { "target": [276, 188, 37, 39] },
        "E_ClickSmallMap1": { "target": [173, 365, 97, 96] }
    }
}
```

`休息` 分支仅设置 `E_CheckTeam1.enabled: false`，使该部队在 SubHub 中自然跳过。

## 自定义动作

### DispatchLogAction

位于 `E_MarkTeam1~5` 和 `E_LogDispatch` 节点中。`mode: "mark"` 记录部队已派遣标记，`mode: "log"` 输出派遣汇总日志到 GUI 面板。

### ExpeditionMapSelectAction

自定义动作，负责根据部队选项选择对应的远征地图坐标。与 `RefreshInterval` 无关（`RefreshInterval` 目前未连接到任何 pipeline_override）。

## 设计要点

- **串行检测**：五个部队按顺序逐一检测，使用 SubHub 级联而非并行，确保依次派遣
- **休息跳过**：`E_CheckTeam1` 默认 `enabled: false`（部队一默认休息），由 GUI 选择地图后 pipeline_override 启用
- **双重验证**：`E_VerifyScreenN` OCR "远征目的地选择" 确保确实在远征画面，避免误操作
- **自循环 home 检测**：`E_DetectHome` 自循环等待本丸加载，`on_error` 回到 Expedition 重新走枢纽
- **忙线处理**：`E_AllTeamsBusy` 在所有部队均不可派遣时（全部在远征中/全部休息）返回本丸
- **动态间隔**：`E_WaitRefresh.post_delay` 由 `RefreshInterval` 选项通过 pipeline_override 动态设置

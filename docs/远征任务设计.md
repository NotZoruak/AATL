# 远征（Expedition）任务设计

## 概述

- 流水线文件：`assets/resource/base/pipeline/Expedition.json`
- 入口节点：`Expedition`（自身即主枢纽，无独立 `*_DetectWhereAmI` 节点）
- 节点前缀：`E_`
- 内嵌子流程：刷花（`E_Flower*`）、部队记录（`E_UseTeamRecord*`）

## GUI 选项

| 选项 | 类型 | 说明 |
|------|------|------|
| 部队一～五 | select | 每队选择远征地图（休息/1-1～5-4 等），默认部队一休息 |
| RefreshInterval | input | 刷新间隔秒数，默认 600 |

```json
{
    "name": "远征",
    "entry": "Expedition",
    "default_check": true,
    "repeatable": false,
    "option": ["部队一", "部队二", "部队三", "部队四", "部队五", "RefreshInterval"]
}
```

部队选项通过 `pipeline_override` 覆盖 `E_SelectMapN` / `E_ClickSmallMapN` 的 `target` 坐标；「休息」把 `E_CheckTeamN.enabled` 设为 false。

## 主枢纽 `Expedition`

入口节点兼主枢纽，`timeout: 120000`，`on_error → E_RestartGame`。

```json
"Expedition": {
    "pre_delay": 0,
    "timeout": 120000,
    "on_error": ["E_RestartGame"],
    "next": [
        "E_LeaveTroopRecord", "E_IsAnnouncementPopup",
        "E_IsTrainingLetter", "E_IsLoginReward",
        "E_ClickExpeditionReturn_Exp", "E_ClickExpeditionReturn_Title",
        "E_DetectExpeditionScreen", "E_IsMenuDirectory",
        "E_IsTeamStatusPanel", "E_CheckHomeBrightness",
        "E_IsGameIcon", "E_IsLoginButton",
        "E_IsGameUpdatePopup", "E_IsInGameUpdatePopup",
        "E_IsInternalReport", "E_IsSwordDropColor",
        "E_FallbackWait"
    ]
}
```

## 主流程链路

```
Expedition（枢纽）
   ├── 远征归来 → E_ClickExpeditionReturn_Exp / _Title
   │     → 点击关闭弹窗 → 回枢纽
   │
   ├── 本丸 → E_CheckHomeBrightness → E_DetectHome
   │     → E_CheckTeamStatus → E_ExpSubHub1..5（串行）
   │
   ├── 派送部队 N（N=1~5 串行）：
   │     E_CheckTeamN → E_SelectTeamN → E_VerifyScreenN
   │       → E_SelectMapN → E_ClickSmallMapN
   │       → E_ConfirmDispatchN → E_SelectTeamBtnN
   │       → E_MarkTeamN → E_StartExpedition
   │       → E_VerifyConfirmPopup → E_ConfirmExpedition
   │       → E_LogDispatch → E_GoHome
   │     （"休息"时 E_CheckTeamN.enabled: false，跳过该队）
   │
   ├── 全忙 → E_AllTeamsBusy → E_GoHome
   │     → E_WaitRefresh（DoNothing + post_delay）→ 回枢纽
   │
   ├── 疲劳处理 → E_CheckFatigue1~5
   │     → E_FlowerNavigate → E_FlowerBattleHub（刷花枢纽）
   │       → E_FlowerCheckCaptain → E_FlowerDone → E_GoHome
   │
   ├── 长期远征计划 → E_UseTeamRecord1~5
   │     → 部队记录页链 → E_StartExpedition
   │
   ├── 回城 → E_GoHome → E_ClickDirectoryTop（OCR "目"）
   │     → E_PostClickDirectoryHub → E_VerifyMenuDir
   │     → E_ClickBackToHome → E_WaitRefresh / E_SmartWait
   │
   └── 闪退恢复 / 弹窗关闭 / E_FallbackWait
```

## 派送流程

五队串行，每队 N 依次执行：

1. `E_CheckTeamN`（OCR 部队编号+状态，`E_IsTeamStatusPanel` 识别后走 `E_ExpSubHubN` 分发）
2. `E_SelectTeamN` → `E_VerifyScreenN`（OCR "远征目的地选择"，失败回 `E_DetectHome`）→ `E_SelectMapN`（点击地图入口，target 由选项 override）→ `E_ClickSmallMapN`（确认地图）
3. `E_ConfirmDispatchN`（OCR 确认出阵）→ `E_SelectTeamBtnN`（on_error → `E_DetectExpeditionScreen`）
4. `E_MarkTeamN`（`DispatchLogAction` mode mark）→ `E_StartExpedition`
5. `E_VerifyConfirmPopup`（OCR "远征确认"）→ `E_ConfirmExpedition`（点击确认，post_delay 4000）
6. `E_LogDispatch`（`DispatchLogAction` mode log）→ `E_GoHome`

## 副枢纽 `E_FlowerBattleHub`

远征内置刷花子流程的独立枢纽，节点前缀 `E_Flower*`。触发条件：`E_CheckFatigue1~5`（`FatigueCheckAction` mode check_all）检测到疲劳 → `E_FlowerNavigate` → 进入此枢纽。

20 个检测节点，`on_error → E_FlowerRestartGame`（与主枢纽 `E_RestartGame` 独立，next 回到 `E_FlowerBattleHub`）。流程：`E_FlowerCheckCaptain` → 刷花完成 → `E_FlowerDone` → `E_GoHome` → 继续远征派遣。

## 计时器系统

| 节点 | 类型 | 说明 |
|------|------|------|
| `E_CheckTimerExpired` | `ExpeditionTimerCheckAction` | 被合战场/地下城/演练引用，检查远征计时到期 |
| `E_TimerStart` | `ExpeditionTimerAction`（mode start） | 启动计时 |
| `E_TimerReset` | `ExpeditionTimerAction`（mode reset） | 重置计时 |
| `E_TrackerOCR` | `ExpeditionTimeTracker` | 默认 disabled，智能调度时启用 |
| `E_SmartWait` | `SmartWaitAction` | 默认 disabled，智能调度时替代固定等待 |
| `E_WaitRefresh` | DoNothing + post_delay | 固定间隔等待 |

## 远征智能调度

全局选项「远征智能调度」默认开启。开启时：

- 合战场/地下城/演练/战术训练的枢纽中插入 `E_CheckTimerExpired`，其他任务行军间隙补派远征
- `E_AllTeamsBusy` → `E_TrackerOCR` → `E_SmartWait`：按远征刷新间隔与剩余时间中更短者动态等待
- `E_WaitRefresh` 禁用，`E_SmartWait` 替代

## 长期远征计划

全局选项「长期远征计划」默认关闭。开启时：

- `E_MarkTeamN` 的 next 改为 `E_UseTeamRecordN`（部队记录快速派遣）
- 附加 `疲劳阈值` 选项，`E_CheckFatigueN`（`FatigueCheckAction` mode check_all）检查疲劳
- 疲劳超阈值 → 刷花子流程恢复 → 继续派遣

## 重启游戏

```json
"E_RestartGame": {
    "action": { "type": "Custom", "custom_action": "RestartGameAction" },
    "next": ["Expedition"]
}
```

另有 `E_FlowerRestartGame`（刷花子流程专用，next → `E_FlowerBattleHub`）。

## on_error 覆盖

- 主枢纽 `on_error → E_RestartGame`
- `E_GoHome`、`E_ClickDirectoryTop`、`E_PostClickDirectoryHub`、`E_VerifyMenuDir` → `Expedition`
- 各队子节点 → `Expedition` 或专用恢复路径（`E_DetectExpeditionScreen` / `E_DetectHome`）
- `E_FlowerBattleHub`（刷花枢纽）`on_error → E_FlowerRestartGame`

## 设计要点

- **无独立枢纽**：入口 `Expedition` 自身即主循环枢纽，超时后触发重启
- **五队串行**：避免并行 OCR 误匹配，每队派完回城再派下一队
- **双枢纽刷花**：疲劳处理走独立副枢纽 `E_FlowerBattleHub`，与主远征隔离
- **计时器跨任务共享**：`E_CheckTimerExpired` 被多个任务引用，行军间隙补派远征

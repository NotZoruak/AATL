# 全局设置设计

## 概述

全局设置对所有任务生效，通过 `interface.json` 的 `global_option` 定义，运行时经 `pipeline_override` 注入到各任务的管道参数中。合并优先级最低（低于 resource option < controller option < task option）。

当前全局选项列表（`interface.json` L162）：

```json
"global_option": ["换队长方式", "远征智能调度", "长期远征计划", "卡死重启"]
```

## 换队长方式

**类型**：select
**默认**：队内拖拽
**影响任务**：合战场（S_）、陆联（LR_）、地下城（U_）

两种方式：

| 方式 | pipleline_override |
|------|--------------------|
| 马匹筛选 | 覆盖 `*_ClickCaptain3.target` 为 `[220,512,107,29]`（刀装筛选按钮位置） |
| 队内拖拽 | 启用 `*_DragCaptain` + `*_IsPreSortieConfirm`，禁用 `*_IsSwordSelect` 和 `*_DetectSortOrder` |

队内拖拽时附加子选项「拖拽跳过位置」（checkbox ×6），勾选后在 `DragCaptainAction` 中跳过对应位置。

## 远征智能调度

**类型**：switch
**默认**：Yes（开启）
**影响任务**：远征（E_）、合战场（S_）、陆联（LR_）、地下城（U_）、战术训练（TT_）

开启后的 pipeline_override：

| 覆盖节点 | 作用 |
|----------|------|
| `LR_IsTeamSelect.next` → `["E_CheckTimerExpired"]` | 陆联部队选择前检查远征计时 |
| `TT_IsTeamSelect.next` → `["E_CheckTimerExpired"]` | 战术训练部队选择前检查 |
| `U_CheckRoundComplete.next` → `["E_CheckTimerExpired"]` | 地下城每轮结束后检查 |
| `E_AllTeamsBusy` → DoNothing + `next: ["E_TrackerOCR"]` | 全忙时 OCR 跟踪剩余时间 |
| `E_TrackerOCR.enabled: true` | 启用时间跟踪 |
| `E_WaitRefresh.enabled: false` | 禁用固定等待 |
| `E_SmartWait.enabled: true` | 启用智能等待（按刷新间隔与剩余时间中更短者） |
| `E_ClickBackToHome.next` → `["E_SmartWait"]` | 回城后智能等待 |
| `E_VerifyLeftMenu.on_error` → `["E_SmartWait"]` | 左侧菜单验证失败走智能等待 |

核心逻辑：按远征刷新间隔与最近远征剩余时间中更短者来调度补派，避免无谓切屏。关闭后 `E_WaitRefresh` 恢复固定间隔等待。

## 长期远征计划

**类型**：switch
**默认**：No（关闭）
**影响任务**：远征（E_）

开启后覆盖各队派遣节点，改用 `E_UseTeamRecordN`（部队记录快速派遣）：

| 覆盖 | 作用 |
|------|------|
| `E_MarkTeam1~5.next` → `["E_UseTeamRecord1~5"]` | 各队标记后走部队记录链 |

附加子选项「疲劳阈值」（input），`E_CheckFatigueN`（`FatigueCheckAction`）按阈值检查疲劳，超阈值先刷花恢复再派遣。

## 卡死重启

**类型**：switch
**默认**：No（关闭）
**影响任务**：全部 9 个 pipeline

### 机制

开启时禁用全部 12 个 `*_FallbackWait` 兜底节点：

```
S_FallbackWait, M_FallbackWait, LR_FallbackWait, FB_FallbackWait,
D_FallbackWait, U_FallbackWait, G_FallbackWait, E_FallbackWait,
E_FlowerFallbackWait, FB_PostFallbackWait, SF_FallbackWait, TT_FallbackWait
```

FallbackWait 通常为 DoNothing → 回枢纽的无限循环。禁用后，当枢纽所有 next 都匹配不上时，不再无限兜底，而是在 timeout 后直接触发 `on_error → *_RestartGame`。

### 子选项

**卡死等待时间**（input，默认 120 秒）：覆盖所有枢纽的 timeout 值：

```
S/M/LR/FB/D/U/G/SF_DetectWhereAmI + Expedition
→ timeout: "{timeout_seconds}000"（毫秒）
```

**目标应用**（input，默认 `com.youzu.djlw`）：`RestartGameAction` 重启时使用的游戏包名。修改此项可适配不同区服。

### 重启流程

```
枢纽超时 → on_error → *_RestartGame → RestartGameAction
  → mumu-cli.exe control --vmindex <n> restart（MuMu 12+）
  → am force-stop <package>（杀游戏进程）
  → monkey -p <package> ... LAUNCHER 1（重启游戏）
  → 回枢纽继续任务
```

## 合并机制

全局选项在 `MaaProcessor.CreateNodeAndParam()` 中合并到每个任务的管道参数，优先级从低到高为：

```
global_option < resource.option < controller.option < task.option
```

后一级的 pipeline_override 可覆盖前一级的值。任务级选项拥有最终决定权。

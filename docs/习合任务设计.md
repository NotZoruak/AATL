### `M_CheckSubLevel`（搓糖控制）

OCR 等级判断 `[401, 299, 46, 27]`，`enabled: false`，搓糖开启时启用。
- 命中（等级 7-10）→ `M_ExitNoMaterial` 跳过该刀剑
- 未命中（等级 1-6）→ `M_ClickSelectAll` 继续习合

> 注意：next/on_error 逻辑经过反转。原设计命中 1-6 走 next 习合、on_error 跳过，因 on_error 不可靠，改为命中 7-10 走 next 跳过、未命中由上级节点 `M_DetectMixSub` 的 next 列表顺延到 `M_ClickSelectAll` 兜底。

```json
"M_CheckSubLevel": {
    "enabled": false,
    "timeout": 1000,
    "recognition": {
        "type": "OCR",
        "param": {
            "roi": [401, 299, 46, 27],
            "expected": ["7", "8", "9", "10"]
        }
    },
    "action": "DoNothing",
    "pre_delay": 300,
    "post_delay": 500,
    "next": ["M_ExitNoMaterial"],
    "on_error": ["M_ClickSelectAll"]
}
```

### 习合主循环链路

```
M_DetectMixSub → M_CheckSubLevel（搓糖开）→ 命中(7-10)→ M_ExitNoMaterial（跳过）
                     ↓ 未命中(1-6)                                     ↑
                M_ClickSelectAll → M_CheckAndMix → M_ConfirmMix1 → M_ConfirmMix2
                     ↓ 失败(M_ExitNoMaterial)                        搓糖开 ↑  │ 搓糖关
                M_ExitNoMaterial                                     └ 等级重检 ←┘  └→ M_ClickSelectAll
                                                                              ↓ 等级≥7
                                                                         M_ExitNoMaterial
```

搓糖开启时 `M_ConfirmMix2` 回到 `M_CheckSubLevel` 重新检测等级，等级达 7 则跳过。搓糖关闭时 `M_ConfirmMix2` 直接回到 `M_ClickSelectAll`。材料耗尽时 `M_ClickSelectAll` 的 3s timeout → `M_ExitNoMaterial` 退出。

> 习合循环链路所有 Click 节点的 `pre_delay` / `post_delay` 统一为 500ms。

**搓糖选项互斥**（pipeline_override 控制）：

| 节点 | 字段 | 搓糖开 | 搓糖关 |
|---|---|---|---|
| `M_CheckSubLevel` | enabled | true | false |
| `M_CheckLevel1~6` | enabled | true | false |
| `M_ClickMixDirect1~6` | enabled | false | true |
| `M_ConfirmMix2` | next | `[M_CheckSubLevel, M_ClickSelectAll]` | `[M_CheckSubLevel, M_ClickSelectAll]` |
| `M_CheckPos1~6` | next | `[Empty, Locked, CheckLevel, ClickMixBtn]` | `[Empty, Locked, CheckLevel]` |
| `M_DetectLocked1~6` | on_error | `[M_CheckLevelN]` | `[M_CheckLevelN]` |

> 搓糖关时 `M_CheckLevelN` 为 `enabled: false`，OCR 被跳过；`M_CheckPosN` 的 next 序列中的 `M_CheckLevelN` 因 disabled 自然跳过，最终落到 `on_error: ["M_DetectWhereAmI"]` 回枢纽。

## 实现变更记录

以下为设计阶段后的实际实现调整：

| 变更 | 原设计 | 实际实现 | 原因 |
|---|---|---|---|
| M_CheckLevel 识别方式 | Custom 动作 `MixLevelCheck` | 标准 OCR `expected: ["7".."10"]` | pipeline_override 的 `enabled` 合并会吞掉 recognition 配置，Custom 动作参数丢失 |

## 不筛选机制

GUI 复选框"不筛选"，pipeline_override 控制两个节点：

| 节点 | 覆盖字段 | 效果 |
|---|---|---|
| `M_HideUnmixable` | `next` → `["M_FilterPostHub"]` | ColorMatch 命中后跳过 `M_ClickFilter`，直通 PostHub |
| `M_DetectMailbox` | `next` → `["M_NoFilterClick1"]` | 不领取邮箱，走四击链路进 PostHub |

`M_NoFilterClick1~4` 默认 `enabled: false`，不筛选开启时启用：

```
M_DetectMailbox → M_NoFilterClick1 [989, 123]
              → M_NoFilterClick2 [799, 157]
              → M_NoFilterClick3 [1009, 303]
              → M_NoFilterClick4 [639, 625]
              → M_FilterPostHub
```

## 已知问题

1. **pipeline_override 覆盖行为**：`enabled: true/false` 的 override 会把整个节点配置替换（而非合并），导致 recognition 等字段丢失。Custom 动作因此无法在 override 场景下使用。
2. **位置检测未完整验证**：五个位置的 ColorMatch 坐标和 OCR ROI 需在实机上进一步校准。

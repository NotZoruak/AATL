# 剪影识别小工具 — 实现设计 v3

> 2026-07-31 | 完整重写，待审阅

## 1. 背景

刀剑乱舞"战术强化训练"活动中，画面右侧有一个 3×3 九宫格。格子初始覆盖彩色涂层（南瓜+紫色火焰装饰）。玩家消耗道具刮开涂层后露出黑色角色剪影。角色剪影随机为上半身(head)或下半身(foot)。玩家根据露出的剪影辨认角色。

目标：一键截图 → 自动识别 → 输出角色名。

## 2. 原版工具 (Silhouette1.0.2) 分析

### 2.1 已知参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 截图分辨率 | 1280×720 | 和 ADB 截图一致 |
| 坐标基准 | 1136×640 | 仅用于坐标映射，不缩放图像 |
| ROI(基准坐标) | `628,207,299,299` | 映射到 1280×720 为 `[708,233,337,337]` |
| 模板 | 232 张 | 和我们的 214 张来源相同，仅命名和数量不同 |
| Unknown 阈值 | 0.55 | 低于此分标记未知 |

### 2.2 实测表现

在用户机器上运行原版，结果：**压切长谷部_head，得分 0.971，方差 0.025/0.005**。此时仅有九宫格第(0,0)格被刮开露出剪影。

### 2.3 算法推断

原版是 NativeAOT 编译的二进制，无法反编译。从 debug 输出（`--debug-output --debug-save-dir`）可观察到：

- 从模拟器窗口截取 1280×720 游戏画面（和我们 ADB 截图起点相同）
- `--base-size 1136,640` 仅用于坐标映射，不缩放图像：ROI `[628,207,299,299]` 映射到 1280×720 后为 `[708,233,337,337]`
- 在 1280×720 图上裁出 337×337 ROI
- 保存 `roi.png`（337×337 彩色）、`marked.png`（标注图）
- 一次识别即输出结果

从 ROI 图的像素分析（337×337 等分 9 格，每格 ≈112px）：

| 格位置 | 灰度均值 | 暗像素%(<80) | 饱和度 | 状态 |
|--------|---------|-------------|--------|------|
| (0,0) | 216 | 12% | 53 | 露出 |
| (0,1) | 177 | 0% | 185 | 涂层 |
| (0,2) | 159 | 0% | 199 | 涂层 |
| (1,0) | 172 | 0% | 195 | 涂层 |
| ... | ... | 0% | >185 | 涂层 |

**关键发现**：涂层格在原版归一化后的图中，灰度<80 的暗像素占比为 0%。这意味着原版使用的二值化阈值 ≤80 时，涂层格完全不产生暗像素，自然不参与匹配。1 个露出格贡献全部得分 (0.971)，其余 8 格贡献 0。

### 2.4 公式推断

得分 0.971 的来源：露出格的暗像素（约 1505 个，占格面积 12%）与压切长谷部_head 模板同位置格的黑像素重叠约 1462 个。`1462/1505 = 0.971`。

公式：**交集(露出格暗像素, 模板格暗像素) / 露出格暗像素**，多格取平均。

方差 0.025/0.005 可能是 Top-1/Top-2 分差，或 head/foot 分差。

## 3. 为什么我们的实现失败

反复尝试了多种方案（整体缩放、中心裁切、饱和度检测、涂层模板匹配、Dice公式、Max聚合），全部失败。

**起点相同**。原版从模拟器窗口截取 1280×720 画面（和我们 ADB 截图一致），其 `--base-size 1136,640` 仅用于坐标映射——ROI `[628,207,299,299]` 映射到 1280×720 后约为 `[708,233,337,337]`。我们最初标定的 ROI `[704,236,343,341]` 与此接近，偏差约 4px。

以下关键点尚未确认，导致反复试错：

1. **二值化阈值**：原版 debug ROI 中涂层格灰度<80 的暗像素为 0%，推测原版阈值 ≤80，但精确值未知
2. **匹配公式**：推测为 `交集/露出暗像素`，与实测得分 0.971 吻合（1462/1505），但我们用相同公式始终得 100%
3. **网格分割**：推测为盲等分，但原版可能有更精确的对齐逻辑
4. **模板二值化**：我们与原版对模板的二值化方式可能不同

## 4. 修正方案

### 4.1 方案A：精确复刻（推荐）

不自己猜测参数，直接从原版 debug 输出中提取中间结果，对比验证每一步：

1. 让用户在原版工具中截图，保存 debug 输出
2. 提取归一化后的完整截图、ROI、每格二值化结果
3. 用我们自己的代码重现完全相同的处理流程
4. 逐像素对比验证每一步与 debug 输出一致
5. 确认一致后再进行匹配

**前提**：需要用户在相同条件下同时运行原版和我们的版本获取截图。

### 4.2 方案B：从原版提取算法

原版 EXE 虽然是 NativeAOT，但其算法逻辑可能通过以下方式推断：

1. 给原版输入不同测试图像，观察输出变化
2. 使用 `--debug-save-dir` 选项保存更详细的中间图像
3. 对比多组输入输出，推断匹配逻辑

### 4.3 方案C：独立设计

放弃复刻原版，从零设计匹配算法：

1. 仅使用饱和度检测（已验证有效：涂层 185+，露出 53）排除涂层格
2. 仅对露出格做二值化和匹配
3. 使用更鲁棒的匹配公式（如归一化互相关 NCC），不依赖二值化阈值

## 5. 素材

模板位于 `resource/silhouette/`，来源为社区剪影数据集经简体中文重命名、人工审阅后的版本。

| 类型 | 数量 | 说明 |
|------|------|------|
| `_head` | 107 | 角色上半身完整九宫格，300×300，黑剪影白底 |
| `_foot` | 107 | 角色下半身完整九宫格，300×300，黑剪影白底 |
| **合计** | **214** | 107 个角色 × 2 种类型，一一配对 |

文件命名格式：`{编号:5位}_{简体中文角色名}_{head|foot}.png`

如 `00003_三日月宗近_head.png`、`00118_压切长谷部_foot.png`。

### 与原版模板的差异

| 维度 | 原版 (Silhouette1.0.2) | 本项目 |
|------|----------------------|--------|
| 数量 | 232 张 | 214 张 |
| 配对 | 含 18 个仅 head 角色 | 全部 head+foot 成对 |
| 命名 | 日文/繁体 | 简体中文 |
| 内容 | 相同来源 | 相同来源，已审阅 |
| 特殊文件 | 含 000170_silhouette_2.png | 已处理，无特殊文件 |

每张 300×300 即为 3×3 网格母版，加载时等分 9 个 100×100 格子蒙版。

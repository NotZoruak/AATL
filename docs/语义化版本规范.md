# 语义化版本规范（SemVer）

MATR 项目的版本号严格遵循[语义化版本 2.0.0](https://semver.org/lang/zh-CN/)规范。

---

## 版本号格式

```
主版本号 . 次版本号 . 修订号 [- 预发布标识]
MAJOR  . MINOR  . PATCH  [- pre-release]
```

- 三个核心数字均为非负整数，**禁止前方补零**
- 预发布标识可选，以连接号 `-` 开头，句点 `.` 分隔
- 示例：`2.13.0`、`2.14.0-alpha.1`、`3.0.0-rc.2`

---

## 递增规则

| 版本号 | 递增时机 | 典型场景 |
|---|---|---|
| **主版本号** | 做了不兼容的 API 变更 | 删除旧字段、改变接口签名、废弃核心功能 |
| **次版本号** | 做了向下兼容的新增功能 | 新增识别节点、新任务类型、新配置项 |
| **修订号** | 做了向下兼容的问题修复 | Bug 修复、性能优化、翻译更新 |

### 归零规则

- 递增**次版本号**时，修订号必须**归零**：`2.13.2 → 2.14.0`
- 递增**主版本号**时，次版本号和修订号均须**归零**：`2.14.0 → 3.0.0`

---

## 预发布版本

用于测试、内测阶段的版本：

- `2.14.0-alpha.1`、`2.14.0-beta.2`、`2.14.0-rc.1`
- 标识符仅允许 ASCII 字母数字和连接号 `[0-9A-Za-z-]`
- 优先级**低于**对应的正式版：`2.14.0-rc.1 < 2.14.0`

### 优先级排序示例

```
2.14.0-alpha < 2.14.0-alpha.1 < 2.14.0-beta < 2.14.0-rc.1 < 2.14.0
```

---

## 初始开发阶段（0.y.z）

主版本号为 0 时表示初始开发阶段，公共 API 不稳定，任何变更都可能不兼容。

- `1.0.0` 是第一个稳定 API 版本

---

## 禁止事项

- **不可修改已发布的版本内容**：任何修改必须以新版本号发布
- **不可使用前导零**：`1.09.0` 不合法，应为 `1.9.0 → 1.10.0`
- **不可使用非数值核心版本号**：`2.x.0`、`1.2.dev` 等不合法

---

## 与 Mirror酱 的关系

Mirror酱 API 的 `current_version` 参数接收 SemVer 格式的版本号，版本比对逻辑依赖 SemVer 优先级规则（`VersionChecker.IsNewVersionAvailable()` 使用 `Semver` NuGet 包解析和比较）。

Mirror酱 使用通道（channel）参数区分稳定性层级：
- `stable` — 对应正式发布版
- `beta` — 对应预发布测试版  
- `alpha` — 对应早期内测版

---

## 构建元信息（可选）

可在版本号后附加 `+` 构建信息，例如 `2.14.0+20240801.sha.abc1234`。构建元信息不参与版本优先级比较，仅用于追溯构建来源。

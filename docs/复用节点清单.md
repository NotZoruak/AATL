### 主枢纽配置

8 个流水线使用 `DetectWhereAmI`（Expedition 使用入口节点 `Expedition`）：

```json
"X_DetectWhereAmI": {
    "pre_delay": 0,
    "timeout": 120000,
    "on_error": ["X_RestartGame"],
    "next": [ ... ]
}
```

**卡死重启开启后**：`timeout` 由"卡死等待时间"覆盖，所有 `FallbackWait` 被禁用，失败穿透到 `RestartGame`。

修复画面直接检出（枢纽命中 IsRepair）：
  IsRepair（OCR "修复"）→ UseSpeedup（Click [1050,580]）

## 全局选项涉及节点

四个全局选项通过 `pipeline_override` 在运行时注入，优先级最低（低于 resource/controller/task option）。

### 卡死重启

**开关**（switch，默认 No）→ 启用 `卡死等待时间` + `目标应用` 子选项。

| 覆盖节点 | 值 |
|----------|-----|
| 全部 12 个 `*_FallbackWait` | `enabled: false` |
| 9 个枢纽 timeout | `{timeout_seconds}000`（毫秒） |

被覆盖的 FallbackWait：`S/M/LR/FB/D/U/G/E/SF/TT_FallbackWait` + `E_FlowerFallbackWait` + `FB_PostFallbackWait`。

被覆盖 timeout 的枢纽：`S/M/LR/FB/D/U/G/SF/TT_DetectWhereAmI` + `Expedition`。

`目标应用`：input，默认 `com.youzu.djlw`，传给 `RestartGameAction` 的 `am force-stop` + `monkey` 命令。

### 远征智能调度

**开关**（switch，默认 Yes）。

开启 case 的 pipeline_override：

| 覆盖节点 | 值 | 说明 |
|----------|-----|------|
| `LR_IsTeamSelect.next` | `["E_CheckTimerExpired"]` | 陆联选队前检查计时 |
| `TT_IsTeamSelect.next` | `["E_CheckTimerExpired"]` | 战术训练选队前检查计时 |
| `U_CheckRoundComplete.next` | `["E_CheckTimerExpired"]` | 地下城每轮后检查计时 |
| `E_AllTeamsBusy` | `action: DoNothing` + `next: ["E_TrackerOCR"]` | 全忙时 OCR 跟踪 |
| `E_TrackerOCR.enabled` | `true` | 启用 ExpeditionTimeTracker |
| `E_WaitRefresh.enabled` | `false` | 禁用固定间隔等待 |
| `E_SmartWait.enabled` | `true` | 启用 SmartWaitAction 动态等待 |
| `E_ClickBackToHome.next` | `["E_SmartWait"]` | 回城后智能等待 |
| `E_VerifyLeftMenu.on_error` | `["E_SmartWait"]` | 验证失败走智能等待 |

关闭 case：无 override。默认行为：`E_WaitRefresh`（DoNothing + post_delay）固定间隔等待，`E_SmartWait` disabled，`E_TrackerOCR` disabled，`E_AllTeamsBusy` Click 关面板 → `E_GoHome`。`IsTeamSelect` 不注入计时检查。其他任务的同步远征 option 仍可正常工作（通过各自的 `E_TimerStart.next` 跳回）。

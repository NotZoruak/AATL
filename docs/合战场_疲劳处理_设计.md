# 合战场 — 疲劳处理功能设计

## 概述

为合战场任务新增「疲劳处理」下拉选项（无 / 刷花 / 停止），在换队长步骤完成后 OCR 检测首位刀剑疲劳值，低于阈值 30 时根据选项执行对应操作。

- 涉及文件：`interface.json`、`resource/base/pipeline/Sortie.json`、`FatigueCheckAction.cs`
- 新增选项：`S_疲劳处理`（select 类型）
- 新增流水线节点：58 个（1 个 `S_FatigueCheck` + 57 个 `SF_` 前缀节点）
- 新增 CustomAction 模式：`FatigueCheckAction` 的 `check_first` 模式

## GUI 选项

### interface.json 修改

合战场任务的 `option` 数组调整为以下顺序（`S_重伤处理` 移至 `S_选择阵形` 之后，`S_疲劳处理` 紧随其后）：

### 路由设计

`S_FatigueCheck` 在 Sortie.json 中的基础定义：

```json
"S_FatigueCheck": {
  "action": {
    "type": "Custom",
    "custom_action": "FatigueCheckAction",
    "custom_action_param": { "mode": "check_first", "threshold": 30 }
  },
  "enabled": false,
  "pre_delay": 100,
  "next": ["S_IsPreSortieConfirm"],
  "on_error": ["SF_Hub"]
}
```

三个选项通过 pipeline_override 精确控制路由：

| 选项 | S_FatigueCheck 覆盖 | SF_Hub 覆盖 | 疲劳<30 行为 |
|------|---------------------|-------------|-------------|
| 无 | 无（`enabled: false` 已是默认） | 无（`enabled: false` 已是默认） | 不检测，跳过 |
| 刷花 | `enabled: true` | `enabled: true` | `return false` → `on_error` → `SF_Hub` |
| 停止 | `enabled: true, on_error: []` | `enabled: false`（默认） | `return false` → `on_error: []` → 终止 |

核心逻辑：`FatigueCheckAction` 在 `check_first` 模式下，疲劳 ≥30 返回 `true` 走 `next` 继续出阵，疲劳 <30 返回 `false` 走 `on_error`。刷花时 `on_error` 指向刷花入口，停止时 `on_error` 为空即终止任务。

## 流水线节点

### 插入点

两种换队长模式各有一个插入点，均在动作完成后、页面回到编队状态时：

- **队内拖拽**：`S_DragCaptain.next` → `S_FatigueCheck`（拖拽完成，编队页面，疲劳 OCR 可见）
- **点击换位**：`S_ConfirmSortAsc.next` → `S_FatigueCheck`（排序确认完毕、点击新队长后回到编队页面）

两个修改都由 `S_换队长` 的 pipeline_override 驱动，只在勾选换队长时生效。`S_FatigueCheck` 默认 `enabled: false`，由 `S_疲劳处理` 控制是否启用检测。

### 节点清单

#### 疲劳检测

| 节点 | 类型 | 说明 |
|------|------|------|
| `S_FatigueCheck` | Custom `FatigueCheckAction` | `mode: "check_first"`, threshold=30，OCR 首位疲劳 |

#### 刷花子流程

共 57 个节点，模式参考 `E_FlowerBattleHub`：一个主枢纽 `SF_DetectWhereAmI` 负责扫描所有游戏状态，各动作节点完成后回枢纽。

## CustomAction 修改

### FatigueCheckAction 新增 `check_first` 模式

在 `Run` 方法中增加 `mode == "check_first"` 分支：

- OCR `FatigueRoisSortie[0]`（出阵编队页面队长位疲劳值），仅读首位
- 将结果写入 `FlowerStateTracker.CurrentFatigueLowest`
- `S_FatigueCheck` 使用标准逻辑（疲劳 ≥30 → `return true`），`SF_CheckFatigue` 通过 `"reversed": true` 反转逻辑（疲劳 <100 → `return true`，常态走 `next` 避免截图）
- 日志前缀统一为 `[疲劳检测-合战场]`

## 设计要点

- **插入位置**：换队长末尾节点之后，利用换队长的编队页面做疲劳 OCR
- **阈值固定**：入口触发 30，刷花目标 100，不做 UI 配置。`SF_CheckFatigue` 逻辑反转（<100 为常态走 next），减少 on_error 截图
- **部队一致**：刷花选部队与合战场出阵部队相同，通过 pipeline_override 同步坐标
- **记录恢复**：刷花完成后使用部队记录槽恢复编队，再导航回合战场目标地图
- **枢纽设计**：`SF_DetectWhereAmI` 为大一统扫描枢纽（参考 `E_FlowerBattleHub`），22 个 next 检测项覆盖弹窗/导航/战斗全状态。所有 `SF_` 节点的 `on_error` 指向 `SF_DetectWhereAmI` 或 `SF_Hub`。`SF_DetectWhereAmI.on_error` 指向 `SF_RestartGame`
- **解散复用**：`SF_DissolveCheck` 的 ColorMatch 参数与 `FB_DissolveCheck` 一致，经过验证
- **on_error 覆盖**：所有 `SF_` 识别节点均需配置 `on_error`（指向 `SF_DetectWhereAmI` 或专用路由），纯路由节点除外

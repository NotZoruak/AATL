# 王点匹配效率优化

## 问题

`S_CheckBossBeforeMarch` 的 next 列表包含全部 8 个时代的 30+ 个 boss 模板匹配节点。当前"王点前撤退"勾选后一次性启用全部，导致每次行军检测都要跑完 30+ 个模板匹配，实测耗时约 1.5 秒。

## 方案

**动态注入**：在 `MaaProcessor.CreateNodeAndParam` 中读取用户选择的时代和地域，代码动态生成非本时代 boss 节点的 `enabled: false`，注入到 `pipeline_override`。

### 实现方式

在 `CreateNodeAndParam` 处理合战场任务时（`entry == "Sortie"`）：

1. 读取 `task.InterfaceItem.Option` 中 `S_选择时代` 的 `SelectedCases`，获取当前选中的时代
2. 读取 `S_选择地域` 的 `SelectedCases`，获取当前地域
3. 根据时代-节点映射表，生成非本时代全部 boss 节点的 `enabled: false`
4. 根据地域-道中映射表，生成非本地域道中节点的 `enabled: false`
5. 合并到 `taskModels` 中，排在 `S_王点前撤退` 的 `enabled: true` 之后

代码位置：`MaaProcessor.CreateNodeAndParam`，在 `UpdateTaskDictionary` 之后、`SerializeTaskParams` 之前。

### 时代-节点映射表（C# 常量）

```
E1: [] (时代一无 boss 节点)
E2: [S_Boss_E2_R1, R2_1, R2_2, R3_1, R3_2, R3_3, R4]
E3: [S_Boss_E3_R1, R2, R3, R4]
E4: [S_Boss_E4_R1, R2, R3, R4]
E5: [S_Boss_E5_R1, R3, R3_2, R4_1, R4_2]
E6: [S_Boss_E6_R1, R2, R3, R4, S_MidRetreat_E6_R1]
E7: [S_Boss_E7_R1, R2_1, R2_2, R3_1, R3_2, R4]
E8: [S_Boss_E8_R1, R2, R3, R4, S_MidRetreat_E8_R1~R4]
```

### 代码逻辑

```csharp
// 所有 boss + 道中节点（43 个）
var allBossNodes = new[] { "S_Boss_E2_R1", ..., "S_MidRetreat_E8_R4" };

// 当前时代启用的节点
var currentEraNodes = GetBossNodesForEra(selectedEra);

// 需要禁用的 = 全部 - 当前时代
var disableNodes = allBossNodes.Except(currentEraNodes);

// 注入 enabled: false
foreach (var node in disableNodes)
    taskModels.Merge("enabled", false, node);
```

### 优势

- **不改 `interface.json`**：无需在 8 个 era case 里写几百行 `enabled: false`
- **不改选项顺序**：`S_王点前撤退` 和 `S_选择时代` 位置不变
- **道中撤退不做细化**：仅 5 个节点，勾选即全部开启，与现有行为一致
- **易维护**：新增 boss 节点只需更新 C# 映射表

### 涉及文件

- `_src/MFAAvalonia/Extensions/MaaFW/MaaProcessor.cs`：新增 boss 节点映射 + 动态注入逻辑
- `interface.json`：无需改动

### 预期效果

- `S_CheckBossBeforeMarch` 有效 next 节点从 30+ 降至 4~8
- 行军检测耗时从 ~1.5s 降至 ~0.2s（热缓存）
- 减少误匹配概率（非本时代模板不参与匹配）
- 道中撤退：`S_选择地域` 可以进一步细化 `S_MidRetreat_*` 的启用（后续优化）
